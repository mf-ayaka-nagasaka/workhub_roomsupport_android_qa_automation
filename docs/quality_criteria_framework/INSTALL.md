# INSTALL — 導入手順

| 項目 | 内容 |
|---|---|
| **象限** | 🛠️ ハウツーガイド |
| **対象者** | フレームワークを自分のプロダクト・リポジトリで使いたい方 |

## 1. パッケージの中身

Zipを展開すると以下の構成になっています。

```
quality-criteria-framework/
├── README.md                          # フレームワークの索引（最初に読む）
├── INSTALL.md                         # ← このファイル
├── docs/
│   ├── 00_tutorial_first_criteria.md      # 🐣 30分で全工程を体験する
│   ├── 01_what_is_quality_criteria.md     # 🧠 定義・目的・役割
│   ├── 02_operation_rules.md              # 📗 ラベル/判定タイミング/逸脱承認
│   ├── 03_metrics_catalog.md              # 📗 指標カタログの使い方・タグ辞書
│   ├── 04_context_profile.md              # 📗 コンテキストプロファイル質問票
│   ├── 05_criteria_template.md            # 📗 判定基準テンプレート
│   ├── 06_default_severity_model.md       # 📗 不具合重要度モデル
│   ├── 07_how_to_prefill_from_source.md   # 🛠️ コードから質問票を下書きする
│   └── 08_how_to_use_skill.md             # 🛠️ Skillで判定基準を作る
├── assets/
│   ├── metrics_catalog.csv                # 指標カタログの初期データ（59行）
│   └── organization_profile_template.md   # 組織プロファイル（導入時に記入するテンプレート）
└── skills/
    └── quality-criteria-generator.md  # Claude Code 用Skill（判定基準ドラフト生成）
```

**このパッケージは自己完結しています。** 他のリポジトリのファイルへの依存はありません。

はじめて使う方は、まず `docs/00_tutorial_first_criteria.md` を30分で通してから実務に入ってください。

## 2. 導入パターン

用途に応じて3通りの使い方があります。

### パターンA：ドキュメントとして読むだけ

Zipを展開して `README.md` から読み始めてください。インストール作業は不要です。
質問票（04）とテンプレート（05）は、そのままコピーして手作業で記入できます。

### パターンB：自分のリポジトリに取り込む（推奨）

```
1. Zipを展開する
2. docs/ と assets/ を、自リポジトリの docs/quality_criteria_framework/ にコピーする
3. skills/quality-criteria-generator.md を、自リポジトリの .claude/commands/ にコピーする
4. Claude Code で /quality-criteria-generator [プロダクト名] を実行する（手順は docs/08_how_to_use_skill.md）
```

コピー後のディレクトリ構成イメージ：

```
<自分のリポジトリ>/
├── .claude/
│   └── commands/
│       └── quality-criteria-generator.md   # ← skills/ からコピー
└── docs/
    └── quality_criteria_framework/
        ├── README.md
        ├── 01_what_is_quality_criteria.md
        ├── ...
        └── 06_default_severity_model.md    # ← docs/ からコピー
```

> **Skillの配置先について:** Claude Code のカスタムコマンドは `.claude/commands/` に置きます。
> 既に同名ファイルがある場合は上書きせず、差分を確認してからマージしてください。

### パターンC：ドキュメント管理ツールに取り込む

Zip内の各 Markdown は、Notion 等のドキュメントツールのページにそのまま貼り付けられます（表・コードブロックも保持されます）。

**指標カタログはデータベース化することを推奨します。** 03 §5「データベースのスキーマ定義」に、
プロパティ定義（型・選択肢）をそのまま設定できる表があります。データは `assets/metrics_catalog.csv` を
インポートすれば59行を一括登録できます。取り込んだDBが以降の**正本**になります（§3 の「指標カタログの正本引き継ぎ」を参照）。

> **表計算ソフトでも運用できます。** セレクト型は入力規則（リスト）、マルチセレクト型はカンマ区切りのテキストに読み替えてください。
> データベース化しない場合は、CSV そのものを正本として扱い、所在を組織プロファイル §4 に記録します。

## 3. 導入後に必ず行う設定

本体ドキュメント（00〜08）は**組織に依存しない内容**です。組織・プロダクト固有の情報は、すべて
`assets/organization_profile_template.md`（**組織プロファイル**）に集約します。

### 手順

```
1. assets/organization_profile_template.md を複製する
   （自リポジトリの docs/ 配下、または Notion 等のページとして）
2. 各節を埋める（下表の順。2 が最優先）
3. 判定基準ドキュメント（05 §2 コンテキストサマリ）から、記入済みプロファイルを参照する
```

### 埋める内容と、埋まらないと書けないもの

| 順 | 組織プロファイルの節 | 内容 | 埋まらないと書けないもの |
|---|---|---|---|
| **1** | **§2 不具合重要度定義** | 自組織の重要度定義の所在、段階↔リリース判定↔ラベルの対応 | **機能適合性の判定基準（FS-01 / FS-02 / FS-12）が1つも書けません** |
| 2 | §4 指標カタログの所在 | 正本DBのURL、初期データの取込日 | 指標の引き当て（03）ができません |
| 3 | §5 測定基盤 | クラッシュ監視・エラー監視・不具合管理・テスト管理等のツール名 | 各指標のデータソース列が埋まりません |
| 4 | §3 承認者ロール | 3つの責務（プロダクト意思決定／技術判断／品質判断）への担当割当 | 逸脱承認フロー（02 §5）が運用できません |
| 5 | §7 TBD 指標の確定期限 | 根拠区分が TBD の指標の期限・担当 | TBD のまま判定フェーズに入るリスクが残ります |
| — | §6 文脈タグの追加 | 既定の辞書で表現できない文脈がある場合のみ | （任意。追加なしでも運用できます） |

記入状況は組織プロファイル §8 のチェックリストで確認できます。

### 指標カタログの正本引き継ぎ

同梱の `assets/metrics_catalog.csv` は**初期データ**です。以下の手順で、自組織のDBへ正本を移します。

```
1. 自組織でデータベースを作成する（スキーマ定義は 03 §5 の表をそのまま設定）
2. assets/metrics_catalog.csv をインポートする（59行）
3. データソース列のプレースホルダー（[不具合管理ツール] 等）を、
   組織プロファイル §5 に記入した実際のツール名に置き換える
4. 組織プロファイル §4 に、DBの所在と取込日を記録する
5. 以降、指標の追加・閾値の調整は自組織のDBに対して行う
```

**手順4以降、正本は自組織のDBです。** 同梱CSVは更新版との差分確認用として保持します（§5 を参照）。

## 4. 動作要件

| 項目 | 要件 |
|---|---|
| ドキュメントの閲覧・編集 | Markdown が読める環境（テキストエディタ / Notion / GitHub 等） |
| Skill の実行 | Claude Code（カスタムコマンドが使える構成） |
| 外部依存 | なし（外部ライブラリ・ツールのインストールは不要） |

Skill を使わず、質問票とテンプレートを手作業で記入する運用でも成立します。

## 5. 更新の受け取り方

本フレームワークは配布時点のスナップショットです。更新版のZipを受け取った場合は、以下に注意してください。

| ファイル | 更新時の扱い |
|---|---|
| 00 / 01 / 02 / 04 / 05 / 06 / 07 | **上書きしてよい**（導入時の設定を再適用する必要あり。§3 を参照） |
| 03 と assets/metrics_catalog.csv | **上書きしない。** 自プロダクトで追加した指標・調整した閾値が失われます。差分を確認してマージしてください |
| 記入済みの組織プロファイル | **上書きしない。** 導入時に埋めた組織固有の設定が失われます。テンプレート側に節の追加があった場合のみ、該当節を追記してください |
| 自プロダクトの判定基準ドキュメント | 本パッケージには含まれないため影響なし |

**指標カタログに独自の指標を追加する場合は、`NEW-01` のようにIDを分けておく**と、更新時のマージが容易になります。
