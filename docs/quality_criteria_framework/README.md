# 品質評価フレームワーク

| 項目 | 内容 |
|---|---|
| **象限** | 🧠 解説・説明（全体の索引） |
| **対象者** | 品質評価計画書を作る・使うすべての方 |
| **ゴール** | 自分が何を読めばよいかが分かり、最初の一歩を踏み出せるようになります |

**プロダクトを問わず再利用できる、品質評価計画書（evaluation plan）の作り方です。** ISO/IEC 25010:2023 を分類軸とし、プロダクトの利用文脈から判定指標と閾値を導き出します。Zipパッケージとして配布されており、自己完結しています。

---

## まず何をするか

**やりたいことで入口が分かれます。**

### A. いま、自プロダクトの判定基準を作る

| 手段 | 進め方 |
|---|---|
| **Claude Code が使える** | `/quality-criteria-generator [プロダクト名]` を実行します（手順は **08**）。質問票の聞き取りから判定基準ドラフトの生成までを対話で行います |
| **手で進める** | **11. 手で品質評価計画書を作る** の手順に沿って進めます。準備から合意までの全工程が1枚にまとまっています |

所要は2〜3時間（開発リーダーとの回答時間を含む）です。**閾値の確定と合意は人が行います。**

### B. 仕組みを理解したい・はじめて触る

**00. はじめての品質評価計画書づくり** を30分で通してください。架空プロダクトで、以下の全工程を体験できます。

| # | やること | 所要時間 | 読むもの |
|---|---|---|---|
| **1** | 練習として、架空プロダクトで判定基準を1枚作ってみる | 30分 | **00. はじめての品質評価計画書づくり** |
| **2** | 自プロダクトの利用文脈を質問票に回答する | 30〜60分（開発リーダーと一緒に） | 04. コンテキストプロファイル質問票 |
| **3** | 指標を引き当て、品質評価計画書に転記して合意を取る | 1〜2時間 | 03. 指標カタログ → 05. 品質評価計画書テンプレート |

> **はじめての方は B を先に通すことをおすすめします。** 仕組みを体験してから実務に入るほうが、結果的に速く終わります。

## このフレームワークが解決する課題

品質評価計画書の流用を阻んでいるのは、指標そのものではなく**閾値を決めた前提（利用文脈）が表に書かれていないこと**です。

例えば設置型タブレットアプリの「24時間稼働で Thermal Status が CRITICAL に到達しないこと」という基準は、*電源を切らず連続稼働する*という文脈から出ています。文脈が書かれていないため、他プロダクトの担当者はこの基準を採用してよいか判断できません。

本フレームワークは、基準表を**毎回パイプラインの出力として生成する**ことでこれを解決します。

```
（任意）ソースコードから質問票の下書きを作成
      ↓
[04] コンテキストプロファイルに回答（対象PFで M群／W群に分岐）
      ↓  対象PF・文脈タグが確定
[03] 指標カタログから該当指標を抽出
      ↓  母集団が確定
[02] 運用ルールに従ってラベル・閾値・根拠を設定
      ↓
[05] テンプレートに転記して判定基準が完成
```

## パッケージと導入

本フレームワークは Zip パッケージとして配布されます。展開すると以下の構成になります。

```
quality-criteria-framework/
├── README.md                          # この索引
├── INSTALL.md                         # 導入手順
├── docs/                              # 00〜11 のドキュメント
├── assets/
│   ├── metrics_catalog.csv                # 指標カタログの初期データ（59行）
│   ├── metrics_catalog_ai_extension.csv   # AI拡張指標の初期データ（10行・AI機能がなければ不要）
│   ├── organization_profile_template.md   # 組織プロファイル（組織に1枚・導入時に記入）
│   ├── product_context_profile_template.md # コンテキストプロファイル（プロダクトに1枚）
│   └── criteria_document_template.md      # 品質評価計画書（リリースごとに1枚）
└── skills/
    └── quality-criteria-generator.md  # Claude Code 用Skill
```

導入手順・導入後に埋める設定・更新版の受け取り方は **INSTALL** にまとめています。

**指標カタログの正本は、導入組織が自組織のデータベースとして持ちます。** 同梱の CSV は初期データです。取り込んだあとは自組織のDBが正本となり、更新はそちらに対して行います（手順は INSTALL §3、所在の記録先は組織プロファイル §4）。

## 収録している記入例

| 例 | 対象PF | 立つ文脈タグ | 収録場所 |
|---|---|---|---|
| 例A：設置型タブレットアプリ（キオスク運用・ハードウェア連携あり） | Android | 常時稼働 / 無人運用 / キオスク運用 / ハードウェア連携 / 外部SDK依存 / OS権限利用 / 個人情報取扱 / 大量データ表示 / オフライン耐性 / リアルタイム同期 / AI機能あり / 非決定的出力 / モデル更新あり / 自動判断 | 04 §8-1、05 §3、06 §5 |
| 例B：顧客向けWebアプリ（データ管理系） | Web | マルチテナント / 個人情報取扱 / 権限ロール / 大量データ表示 / 一括インポート・エクスポート / 長時間セッション / 同時編集 / 帳票出力 | 04 §8-2、06 §5 |

記入例は特定のプロダクトを指すものではなく、**利用文脈の類型**として記載しています。自プロダクトに近い型を出発点にしてください。
