# 品質判定基準フレームワーク

| 項目 | 内容 |
|---|---|
| **象限** | 🧠 解説・説明（全体の索引） |
| **対象者** | 品質判定基準を作る・使うすべての方 |
| **ゴール** | 自分が何を読めばよいかが分かり、最初の一歩を踏み出せるようになります |

**プロダクトを問わず再利用できる、品質判定基準の作り方です。** ISO/IEC 25010:2023 を分類軸とし、プロダクトの利用文脈から判定指標と閾値を導き出します。Zipパッケージとして配布されており、自己完結しています。

---

## まず何をするか

はじめての方は、**この3ステップだけ**見てください。

| # | やること | 所要時間 | 読むもの |
|---|---|---|---|
| **1** | 練習として、架空プロダクトで判定基準を1枚作ってみる | 30分 | **00. はじめての品質判定基準づくり** |
| **2** | 自プロダクトの利用文脈を質問票に回答する | 30〜60分（開発リーダーと一緒に） | 04. コンテキストプロファイル質問票 |
| **3** | 指標を引き当て、判定基準表に転記して合意を取る | 1〜2時間 | 03. 指標カタログ → 05. 判定基準テンプレート |

**ステップ1を飛ばさないでください。** 仕組みを体験してから実務に入るほうが、結果的に速く終わります。

Claude Code が使える環境では、`/quality-criteria-generator [プロダクト名]` でステップ2〜3のドラフト生成を支援できます。手順は **08. Claude Code のSkillで品質判定基準を作る** にまとめています。

## このフレームワークが解決する課題

品質判定基準の流用を阻んでいるのは、指標そのものではなく**閾値を決めた前提（利用文脈）が表に書かれていないこと**です。

例えば設置型タブレットアプリの「24時間稼働で Thermal Status が CRITICAL に到達しないこと」という基準は、*電源を切らず連続稼働する*という文脈から出ています。文脈が書かれていないため、他プロダクトの担当者はこの基準を採用してよいか判断できません。

本フレームワークは、基準表を**毎回パイプラインの出力として生成する**ことでこれを解決します。

```
（任意）ソースコードから質問票の下書きを作成
      ↓
[04] コンテキストプロファイルに回答（対象PFで M群／W群に分岐）
      ↓  対象PF・文脈タグが確定
[03] 指標カタログから該当指標を抽出
      ↓  母集団が確定
[02] 運用ルールに従ってラベル・閾値・根拠を設定
      ↓
[05] テンプレートに転記して判定基準が完成
```

## パッケージと導入

本フレームワークは Zip パッケージとして配布されます。展開すると以下の構成になります。

```
quality-criteria-framework/
├── README.md                          # この索引
├── INSTALL.md                         # 導入手順
├── docs/                              # 00〜08 のドキュメント
├── assets/
│   └── metrics_catalog.csv            # 指標カタログのスナップショット（59行）
└── skills/
    └── quality-criteria-generator.md  # Claude Code 用Skill
```

導入手順・導入後に埋める設定・更新版の受け取り方は **INSTALL** にまとめています。

**指標カタログの正本は Notion データベースです。** CSV はスナップショットなので、更新は Notion 側に対して行ってください。

## 収録している記入例

| 例 | 対象PF | 立つ文脈タグ | 収録場所 |
|---|---|---|---|
| 例A：設置型タブレットアプリ（キオスク運用・ハードウェア連携あり） | Android | 常時稼働 / 無人運用 / キオスク運用 / ハードウェア連携 / 外部SDK依存 / OS権限利用 / 個人情報取扱 / 大量データ表示 / オフライン耐性 / リアルタイム同期 | 04 §8-1、05 §3、06 §5 |
| 例B：顧客向けWebアプリ（データ管理系） | Web | マルチテナント / 個人情報取扱 / 権限ロール / 大量データ表示 / 一括インポート・エクスポート / 長時間セッション / 同時編集 / 帳票出力 | 04 §8-2、06 §5 |

記入例は特定のプロダクトを指すものではなく、**利用文脈の類型**として記載しています。自プロダクトに近い型を出発点にしてください。
