# 03. 指標カタログ

| 項目 | 内容 |
|---|---|
| **象限** | 📗 リファレンス |
| **対象者** | QA担当（基準ドラフト作成者） |
| **ゴール** | 対象PFと文脈タグでカタログを絞り込み、自プロダクトに必要な判定指標を過不足なく選び出せるようになります |

指標の実体は**全59指標**あり、初期データを `assets/metrics_catalog.csv` として同梱しています。**導入組織は自組織のデータベースに取り込み、以降はそちらを正本として運用します。** 本書はその**使い方・タグ辞書・スキーマ定義**を扱います。

---

## 1. 指標データの所在

| 形式 | 用途 | 場所 |
|---|---|---|
| **自組織のデータベース** | **正本。** 絞り込み・並べ替え・更新はここで行います | 組織プロファイル §4 に記載 |
| CSV（`assets/metrics_catalog.csv`） | **初期データ。** 自組織のDBへ取り込む際に使います。取込後は正本ではありません | 本パッケージ内 |

### 正本の引き継ぎ

導入時に、以下の手順で正本を自組織に移します（詳細は INSTALL §3）。

```
自組織でDBを作成（スキーマは §5）→ CSVをインポート（59行）
  → データソース列のプレースホルダーを実ツール名に置換
  → 組織プロファイル §4 に所在を記録 → 以降そちらが正本
```

> **引き継ぎ後、更新は自組織の正本DBに対して行ってください。** 同梱CSVを直接編集しても正本には反映されません。CSVは更新版パッケージとの差分確認用として保持します。

> **DBを作らない運用も可能です。** その場合はCSV（または表計算ソフトに取り込んだもの）を正本とし、所在を組織プロファイル §4 に記録してください。

## 2. このカタログの使い方

```
[1] コンテキストプロファイル（04）に回答する
      ↓
[2] 「対象PF」で絞る            … Android / iOS / Web / 共通
      ↓
[3] 「文脈タグ」で絞る          … 該当タグを持つ指標のみ採用
      ↓
[4] 「推奨初期値」を仮置きする  … 実測が必要なものは TBD のまま残す
      ↓
[5] 判定基準テンプレート（05）に転記し、閾値を確定・合意する
```

**文脈タグが付いていない指標は「無条件で採用候補」です。** タグ付き指標は、該当する文脈を持つプロダクトでのみ採用します。

採用指標の決まり方は以下のとおりです。

```
採用指標 =（対象PFが一致する指標）
        ∩（文脈タグなし ∪ 立ったタグを持つ指標）
        −（測定手段がないと判明した指標）
```

## 4. 文脈タグ辞書

文脈タグは**閾値の根拠になっている利用条件**を表します。タグを見れば「なぜこの指標が必要か」が分かる状態を保ちます。

### 4-1. 運用形態

| タグ | 意味 | 代表プロダクト |
|---|---|---|
| `常時稼働` | 電源を切らず連続稼働し続ける | 設置型タブレット、サイネージ |
| `無人運用` | 異常時にその場で人が復旧できない | 設置型タブレット、キオスク端末 |
| `キオスク運用` | 単一アプリ固定・他アプリへの離脱を想定しない | 設置型タブレット |
| `ハードウェア連携` | 外部デバイスの制御を伴う | 施解錠デバイス、生体認証デバイス |
| `バックグラウンド動作` | アプリがバックグラウンドへ回る前提の運用 | 一般的なモバイルアプリ |
| `OS権限利用` | カメラ・位置情報・通知等のOS権限を要求する | 生体認証、位置連動機能 |

### 4-2. データ・テナント

| タグ | 意味 | 代表プロダクト |
|---|---|---|
| `マルチテナント` | 複数の顧客組織のデータを同一基盤で扱う | 顧客向けWebアプリ |
| `個人情報取扱` | 個人情報・生体情報を保持する | 生体認証、会員管理 |
| `大量データ表示` | 一覧・検索で数千件以上を扱う | データ管理系Webアプリ |
| `一括インポート・エクスポート` | CSV等での一括登録・出力機能を持つ | データ管理系Webアプリ |
| `権限ロール` | ロールによって可視範囲・操作範囲が変わる | 管理画面、Webアプリ |
| `同時編集` | 複数ユーザーが同一データを同時に更新しうる | データ管理系Webアプリ |
| `帳票出力` | PDF・帳票・印刷など整形された出力物を生成する | データ管理系Webアプリ |

### 4-3. 通信・セッション

| タグ | 意味 | 代表プロダクト |
|---|---|---|
| `オフライン耐性` | ネットワーク断でも一定の機能継続が求められる | 設置型タブレット |
| `リアルタイム同期` | サーバー側の変更が即時に画面へ反映される必要がある | 状況表示、共同編集 |
| `長時間セッション` | 1セッションが数時間に及ぶ想定 | 業務系Webアプリ |
| `外部SDK依存` | サードパーティSDKの成否ハンドリングが必要 | 生体認証SDK、決済SDK |

## 5. データベースのスキーマ定義

指標DBのプロパティ定義です。自組織でDBを作る場合は、この定義をそのまま設定してください。

| プロパティ名 | 型 | 選択肢・備考 |
|---|---|---|
| 指標ID | タイトル | `FS-01` 等。特性プレフィックス＋連番 |
| 指標名 | テキスト | 判定基準の本文になる文言 |
| ISO特性 | セレクト | ISO/IEC 25010:2023 の9特性 |
| 対象PF | マルチセレクト | 共通 / Android / iOS / Web |
| 文脈タグ | マルチセレクト | §4 のタグ辞書を参照 |
| 推奨ラベル | セレクト | P1 / P2 / P3（採用時に見直し可） |
| 推奨初期値 | テキスト | 閾値。確定できないものは `TBD` |
| 測定方法 | テキスト | 手順レベルで記述 |
| データソース | テキスト | 具体的なツール・ダッシュボード名。初期データではプレースホルダー（`[不具合管理ツール]` 等）になっているため、組織プロファイル §5 に記入したツール名へ置き換えます |
| 判定タイミング | セレクト | 継続測定 / テストフェーズ完了時 / RC版での測定 / 長期測定 / リリース判定会議時点 |
| 根拠区分 | セレクト | 業界基準 / 組織標準 / 実測ベース / 契約・SLA由来 / チーム合意 / TBD |
| 出典URL | URL | 根拠区分が「業界基準」「組織標準」の場合は必須 |
| 採用実績 | リレーション | 採用したプロダクト・リリースへのリレーション |

> **ビューの作り方:** 「対象PF」でフィルタしたビューを PF ごとに用意しておくと、新規プロダクトの立ち上げ時にそのまま母集団として使えます。

> **実装形式は問いません。** 上記はプロパティ型をセレクト・マルチセレクトで表現できるツール（Notion 等）を想定した書き方です。表計算ソフトで運用する場合は、セレクトを「入力規則（リスト）」、マルチセレクトを「カンマ区切りのテキスト」に読み替えてください。

## 6. 出発点となった既存基準からの変換対応表

本フレームワークの出発点となった既存の品質判定基準（設置型タブレットアプリ向け・16項目）が、本カタログのどこに対応するかを示します。一般化の考え方を示す事例として収録しています。

| 元の判定基準 | 対応ID | 変換時の扱い |
|---|---|---|
| 未対応重大不具合件数（Emergency / Critical / Major） | FS-01 / FS-02 | **自組織の重要度定義のリリース判定に従って分割。** 「リリース不可」の段階は FS-01（P1）、「条件付きリリース可」の段階は FS-02（P2）。変換ルールは 06 §3 |
| 未対応中程度不具合件数（Normal以下） | FS-12 | P3（記録のみ）に変更。「リリース可」の段階は合否判定に使わず、件数を記録します |
| 業務シナリオテスト通過率 | FS-03 | そのまま共通指標化 |
| サポートOS×端末の動作保証 | CO-01 | 閾値90%は「チーム合意」に分類。Web版 CO-02 を新設 |
| クラッシュフリー率 | RE-01 | 対象PFをモバイルに限定。Web は RE-06 に分離 |
| ANR発生率 | RE-02 | Android専用として維持 |
| ロングラン検証結果 | RE-03 | 文脈タグ `常時稼働` を付与 |
| クラッシュ復帰時間 | RE-04 | 文脈タグ `無人運用` を付与 |
| E2E応答時間（認証→デバイス制御完了） | PE-01 | 固有のデバイス名を外し「デバイス制御」に一般化 |
| E2E応答時間（特定業務データの作成） | PE-02 | 「主要データ書き込み操作」に一般化し共通指標化 |
| メモリ使用量・メモリリーク | PE-03 / PE-04 | **2指標に分割**（瞬間値と増加量は測定方法が異なるため） |
| バッテリー消費・発熱 | PE-05 / PE-12 | **2指標に分割**（常時給電機器では発熱のみが論点になるため） |
| 大量データ時の容量耐性 | PE-07 | 件数をプロダクト依存値として外し、タグ `大量データ表示` を付与 |
| CPU使用率 | PE-06 | 状態別の表現を「高負荷処理中／待機時」に一般化 |
| 分析可能性（ログ・監視） | MA-01 / MA-02 | **2指標に分割**（アプリログとクラッシュログは確認先が異なるため） |
| 「それ以外は都度評価必要」 | — | **廃止。** 02 の「スコープ外宣言のルール」で特性ごとに明示する方式へ変更 |

### 一般化にあたっての判断

- **プロダクト固有の語を指標名から排除しました**（個別のデバイス操作名 → 「デバイス制御」、個別の業務名 → 「主要データ書き込み操作」）。固有性は指標名ではなく**文脈タグ**で表現します
- **測定方法が異なるものは指標を分割しました。** 1指標に複数の測定が混在すると、片方だけ測って Pass にしてしまうためです
- **プロダクト依存の数値は推奨初期値から外しました。** 04 のコンテキストプロファイルで確定させます

## 8. カタログの保守ルール

| トリガー | 対応 |
|---|---|
| リリース後に実測値が出た | 該当指標の「推奨初期値」と「根拠区分」を更新します（TBD → 実測ベース） |
| 新しいプロダクトで固有指標が必要になった | 文脈タグを新設し、指標を追加します。既存指標の書き換えはしません |
| 同じ指標が3プロダクト以上で採用された | 文脈タグを外し、無条件採用候補に格上げすることを検討します |
| 逸脱承認が繰り返されている指標がある | 閾値が実態に合っていない可能性があります。根拠を再確認して見直します |

> **文脈タグを新設したら、必ず 04 の質問票にも対応する設問を追加してください。** タグだけ増やすと、そのタグを立てる手段がなくなります。

自プロダクト固有の指標を追加する場合は、`NEW-01` のようにIDを分けてください（接頭辞は組織プロファイル §4 に記録します）。カタログの更新版を受け取ったときのマージが容易になります。
