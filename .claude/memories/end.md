### [2026-10-29] 指摘事項_2
- **対象タスク**: PR作成（/end）／追加コミットのプッシュ
- **対象機能**: review-bdd-artifacts スキル定義の更新（コミット `a408e9d`）
- **指摘カテゴリ**: 手順の前提確認漏れ（既存PRが OPEN かを確認せずにプッシュし、案内も誤った）
- **指摘された内容**: PR #28 作成後に追加のコミットを作り、「このままプッシュすると PR #28 に積まれます」と案内してプッシュした。実際には PR #28 は既に MERGED（15:16）で、追加コミット（16:14）はマージ後だったため**どのPRにも載らず、main にも入らなかった**。さらにマージ済みPRに対してタイトル・本文の編集まで行った（反映はされたが無意味）。`gh pr list --state open` が空だったことにも気づいていなかった。
- **原因/理由**: 指摘事項_1 の対策「**プッシュの前に** `gh pr list --head <ブランチ名> --state open` を実行する」を、**セッション冒頭の1回だけ実行して以降は再確認しなかった**。PRは自分がプッシュしていない間にユーザーがマージできるため、PRの状態は時間とともに変わる。「一度確認したから同じはず」という前提を置いたのが誤り。また「PRに積まれます」と断定して案内し、その根拠を取り直さなかった。
- **今後の対策**: ①**プッシュのたびに**（セッション中の2回目以降も必ず）`gh pr view <番号> --json state` または `gh pr list --head <ブランチ名> --state open` を実行し、PRが OPEN であることを確認してからプッシュする。②「このPRに積まれます」と案内する前に、その場で state を取得して根拠にする。③プッシュ後も `git merge-base --is-ancestor <コミット> origin/main` で、意図した先に入ったかを検証してから完了報告する。
