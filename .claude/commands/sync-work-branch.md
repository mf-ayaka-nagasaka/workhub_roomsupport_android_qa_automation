# Skill: sync-work-branch
作業開始前にmainブランチを同期し、作業ブランチへマージ、さらにリリースVer（タグ）の整合性を確認します。

## Usage
`/sync-work-branch [作業用ブランチ名] [期待するリリースVer（例：v1.2.0）]`

## Context / Scope
- **対象**: Gitリポジトリ操作
- **前提条件**: ローカルに未コミットの変更がないこと。

## Instructions
あなたはシニアQAエンジニアとして、テスト環境を最新かつ正しいバージョンに整えてください。

### 1. 調査・分析 (Investigation)
- `git status` でクリーンな状態か確認。
- `git fetch --tags` を実行し、最新のタグ情報を取得。

### 2. 実行・加工 (Action)
- **main同期**: `git checkout main` -> `git pull`。
- **ブランチ統合**: `git checkout [作業用ブランチ名]` -> `git merge main`。
- **Verチェック**: `git describe --tags --abbrev=0` で取得した現在のタグと、引数の `[期待するリリースVer]` を照合。
  - **不一致の場合**: 「現在のタグは[実際のタグ]ですが、指定は[期待値]です。タグの打ち直しが必要ですか？」と警告を表示。

### 3. レポート・完了報告 (Reporting)
- 同期完了の報告。
- バージョン照合結果（一致/不一致）。
- コンフリクトの有無。

## Constraints (制約事項)
- 勝手にタグを新規作成したり削除したりしないこと。
- コンフリクト時は直ちに停止し、ユーザーに報告すること。

2. **成果物の再生成に伴う自動蓄積（トリガールール）**:
   - ユーザーの指摘や修正指示によって、一度生成した成果物を作り直す場合、それは「初期出力に考慮漏れやルールの不一致があった」ことを意味します。

   **【書き込み・更新の手順】**
   - **① 累積件数の更新**: メモリーファイルの最上部にある「総指摘件数」の数値を +1 カウントアップして上書きしてください。

     - **対象タスク**: （例: 影響範囲の抽出、テスト観点作成など）

     - **今後の対策**: （例: 認証が絡む変更の際は必ずログインケースを強制抽出する）

3. **完了報告**:
