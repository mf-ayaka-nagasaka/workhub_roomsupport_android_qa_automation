# Skill: skill-improver
既存のSkillに対する課題・バグ・改善要望を受け取り、対象Skillを調査し、改善案を提案・承認後に適用する自己改善Skillです。

## Usage
`/skill-improver [対象スキル名] "[課題・改善要望]"`

例: `/skill-improver qa-workflow-manager "各Stepで参照ドキュメントを読みに行かない問題を修正したい"`

## Context / Scope
- **対象ファイル**: `.claude/commands/{対象スキル名}.md`
- **関連メモリー**: `.claude/memories/{対象スキル名}.md`、`.claude/memories/global.md`
- **スキル一覧**: `.claude/commands/README.md`
- **変更対象**: スキル定義ファイル（`.claude/commands/*.md`）のみ

## Instructions
あなたはSkillの設計・改善を専門とするエンジニアとして振る舞います。
【最重要ルール】：提案（Step 2）でユーザーの承認を得るまで、対象ファイルの書き換えは絶対に行わないでください。

### Step 1: 調査 (Investigate)

> **【必読】このStepを開始する前に、以下のファイルを必ず Read で読み込んでから作業を開始すること：**
> - `.claude/commands/{対象スキル名}.md`（対象スキル定義）
> - `.claude/memories/{対象スキル名}.md`（対象スキルの過去の指摘事項。存在しない場合はスキップ）
> - `.claude/commands/README.md`（スキル一覧と標準ワークフロー）

1. 対象スキルファイルを読み込み、セクション構造・処理フロー・引数仕様を把握する
2. 関連メモリーファイルが存在すれば読み込み、過去の指摘事項（同種の課題が既出でないか）を確認する
3. 課題内容に応じて、以下の追加調査を行う：
   - 他のスキルとの依存関係がある場合 → 関連スキルファイルも Read で読み込む
   - スキルが参照するデータファイルやテンプレートに関連する課題 → 該当ファイルの存在・構造を確認する
   - 実行時の挙動に関する課題 → 類似スキルでの実装パターンを比較する
4. 調査結果を以下のフォーマットでユーザーにレポート出力する：

```
## 調査レポート

### 対象スキル
- ファイル: `.claude/commands/{スキル名}.md`
- 概要: （スキルの1行説明）

### 課題の分析
- **課題**: （ユーザーから受け取った課題の要約）
- **原因箇所**: （スキルファイル内の該当セクション・行の特定）
- **原因の詳細**: （なぜこの問題が発生しているかの分析）

### 過去の関連指摘
- （メモリーに同種の指摘があれば記載。なければ「なし」）

### 影響範囲
- （他スキルへの影響有無と詳細）
```

レポート出力後、ユーザーの確認を待つ。ユーザーから「分析が違う」「別の箇所が原因」等の指摘があれば再調査する。

### Step 2: 提案 (Propose)

ユーザーが調査レポートを確認後（「OK」「次へ」等の合意を得てから）、改善案を作成する。

1. 具体的な改善案を**修正前 → 修正後の差分形式**で提示する：

```
## 改善提案

### 変更概要
（何をどう変えるかの1-2行の要約）

### 変更箇所 1: （セクション名）

**修正前:**
（該当箇所の現在のテキスト）

**修正後:**
（改善後のテキスト）

**変更理由:**
（なぜこの変更が課題を解決するかの説明）

### 変更箇所 2: ...
（必要に応じて複数の変更箇所を列挙）

### 影響範囲の確認
- 他スキルへの影響: （あり/なし + 詳細）
- 既存の処理フローへの影響: （あり/なし + 詳細）
```

2. 提案の最後に、ユーザーへ以下の選択肢を提示する：
   - **「OK」「適用して」** → Step 3 へ進む
   - **修正の指摘** → 指摘内容を反映して再提案（Step 2 をやり直す）
   - **「やめる」「中止」** → 処理を中断して終了する

### Step 3: 適用 (Apply)

ユーザーの明示的な承認（「OK」「適用して」等）を得た場合のみ実行する。

1. 対象スキルファイルに対して、提案した変更を Edit ツールで適用する
2. 変更後のファイルの該当箇所を出力し、意図通りに変更されていることをユーザーに確認してもらう
3. 確認OKを得たら、以下のGit操作を実行する：
   - `git add .claude/commands/{対象スキル名}.md`
   - `git commit -m "skill: {対象スキル名} を改善（{課題の要約}）"`
4. 完了レポートを出力する：

```
## 完了レポート
- **対象スキル**: {スキル名}
- **変更内容**: （変更の要約）
- **コミット**: （コミットハッシュ）
```

## Constraints (制約事項)
- **変更対象の限定**: `.claude/commands/*.md`（スキル定義ファイル）のみを変更対象とする。ソースコード、データファイル、テンプレート等は変更しない。
- **承認必須**: Step 2 の提案に対するユーザーの明示的な承認なしに、ファイルの書き換えを行わない。
- **1スキル限定**: 1回の実行につき、変更対象は1つのスキルファイルのみとする。複数スキルにまたがる改善は、個別に実行する。
- **テンプレート構造の維持**: 「自己学習および指摘の蓄積ルール」セクションのテンプレート構造（累積件数、指摘フォーマット）は変更しない。
- **破壊的変更の防止**: セクション構造（Usage, Context/Scope, Instructions, Constraints）の大枠を削除・統合しない。セクション内の内容を改善する。

## 自己学習および指摘の蓄積ルール（最重要）

本スキルを実行する際、以下の記憶の読み込みと書き込みのプロセスを必ず実行してください。
【厳守】: 本Skillの定義ファイル自体は絶対に編集・上書きしないでください。

1. **実行前の記憶確認**:
   - タスクを開始する前に、必ず `.claude/memories/global.md` および `.claude/memories/skill-improver.md` を読み込み、過去の指摘事項を最優先のルールとして適用してください。

2. **成果物の再生成に伴う自動蓄積（トリガールール）**:
   - ユーザーの指摘や修正指示によって、一度生成した成果物を作り直す場合、それは「初期出力に考慮漏れやルールの不一致があった」ことを意味します。
   - 成果物を再生成する**前に**、自律的に `.claude/memories/skill-improver.md` へ物理的にファイル編集を行って追記・更新してください。

   **【書き込み・更新の手順】**
   - **① 累積件数の更新**: メモリーファイルの最上部にある「総指摘件数」の数値を +1 カウントアップして上書きしてください。
   - **② 指摘内容の追記**: 既存の内容を消さずに、以下のフォーマットに従ってファイルの末尾に追記してください。

     ### [YYYY-MM-DD] 指摘事項_{連番}
     - **対象タスク**: （例: 影響範囲の抽出、テスト観点作成など）
     - **対象機能**: （例: ログイン画面、決済APIなど）
     - **指摘カテゴリ**: （例: 網羅性の不足、仕様の誤認識、具体性の不足、フォーマット違反 など）
     - **指摘された内容**: （例: 重点確認ケースに「ログイン周り」が抜けている）
     - **原因/理由**: （例: 依存関係の読み込みが甘かったため）
     - **今後の対策**: （例: 認証が絡む変更の際は必ずログインケースを強制抽出する）

3. **完了報告**:
   - 指摘事項のファイルへの書き込み（総件数の更新と末尾への追記）が完了し、成果物の再生成も終わったら、ユーザーへ「指摘内容をメモリーに蓄積し、総指摘件数を〇件に更新した上で、成果物を作り直しました」と必ず報告してください。
