# Skill: qa-feature-extractor
ソースコード、画面マッピング、および過去の機能一覧を解析し、QA標準用語を適用した「最新の機能一覧（関連画面紐付き）」を抽出します。
出力先ファイルが存在しない場合は新規作成し、既に存在する場合は差分を比較して自動更新します。

## Usage
`/qa-feature-extractor`

## Context / Scope
- **出力・更新ファイル**: `docs/features_list.md` （※出力先パス）
- **参照用データ（粒度の把握）**: `data/機能一覧.csv`
- **参照ドキュメント（命名規則）**: `C:\Users\mforce0087\[Androidソースリポジトリ]\documents\RoomSupport\qa_naming_definition.md`
- **マッピング定義**: `C:\Users\mforce0087\[Androidソースリポジトリ]\documents\RoomSupport\screen-map.yml`
- **対象ファイル**: プロダクトのソースコード（ルーティング定義、ViewModel、Screen/Composableコンポーネント等）

## Instructions
あなたはシニアQAエンジニアとして振る舞ってください。
以下のステップで、最新の実装に基づいた機能一覧を洗い出し、ドキュメントを更新してください。

### 1. インプットと学習 (Preparation)
- `data/機能一覧.csv` を読み込み、QAとしてテスト設計を行う上で適切な「機能の粒度」を学習してください。
- `docs/qa_naming_definition.md` を読み込み、出力時に使用すべき正しいQA標準用語をインプットしてください。
- `docs/screen-map.yml` を読み込み、現在定義されている画面とソースコードの紐付け関係を把握してください。

### 2. 調査・分析 (Investigation)
- `screen-map.yml` に記載されているソースコードを中心に解析し、「どのような機能（Feature）が存在するか」をグループ化して抽出してください。
- 画面単体の情報だけでなく、コード上のEnum（列挙型）やAPIリクエストのまとまりも機能抽出の根拠として利用してください。

### 3. 実行・比較・更新 (Action & Update)
- 出力・更新対象である `docs/features_list.md` の存在確認を行ってください。
- **ファイルが存在しない場合**:
  - 抽出した機能一覧を、以下の【出力フォーマット】に従ってMarkdownの表形式で新規作成し、保存してください。
- **ファイルが既に存在する場合**:
  - 既存の `docs/features_list.md` の内容を読み込み、今回ソースコードから抽出した最新の機能一覧と比較（Diff）してください。
  - ソースコード上で追加された新機能の追加、変更された画面紐付けの修正、廃止された機能の削除を行い、ファイルを最新状態に「更新（上書き）」してください。
  - ※既存ファイルに人間が追記した「備考」や「ドメイン固有のメモ」列がある場合は、極力その内容を保持したままマージしてください。

【出力フォーマット（Markdown表）】
| 大機能 | 小機能（抽出した機能） | 関連する画面（screen-map.yml準拠） | 抽出根拠（コードのパスやEnum名） |
|---|---|---|---|
| 例: 認証 | 例: 顔認証（2DAS/3DAS） | ログイン画面、認証設定画面 | `src/features/auth/FaceAuthType.ts` |

### 4. レポート・完了報告 (Reporting)
- ターミナル上で、以下の更新サマリーを報告してください。
  - ファイルを新規作成したか、更新したか。
  - **差分（Diff）のサマリー**: 追加された機能、削除された機能、変更された機能のリスト。

## Constraints (制約事項)
- ソースコードおよび参照用ドキュメント（CSVやyml等）は絶対に書き換えないこと（読み取り専用）。
- 抽出した機能名や画面名には、ソースコード上の生の変数名ではなく、必ず `docs/qa_naming_definition.md` の標準用語を使用すること。
