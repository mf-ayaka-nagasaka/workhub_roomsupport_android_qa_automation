# Skill: qa-impact-analyzer
修正内容から影響範囲を特定し、既存テストケースを抽出・レポートするスキルです。

## Usage
`/qa-impact-analyzer [ver] [ticket_no]`
例: `/qa-impact-analyzer 5.6.0 WSS-1613`

## Context / Scope
- **修正内容ファイル**: `v[ver]_[ticket_no].md`
- **影響機能の抽出**: `C:\Users\mforce0087\workhub_roomsupport_android_qa_automation\data\templates\機能一覧.csv`
- **テストケースの抽出**: `C:\Users\mforce0087\workhub_roomsupport_android_qa_automation\data\testcases\ROOM_03_cleaned.csv`

## Instructions
あなたはシニアQAエンジニアとして、修正内容の影響範囲を特定してください。

### 1. 修正内容の把握
- 引数から対象ファイル `v[ver]_[ticket_no].md` を読み込み、修正箇所を把握します（※もしこの時点でファイル内にテスト観点が記載されていれば、それも読み込みます）。

### 2. 影響範囲の特定
- `index.md` を参照し、キーワードを抽出。巨大なCSVファイル群に対して `grep -E` 等のシェルコマンドを使用し、該当するテストケースをフィルタリング・抽出します。

### 3. レポート出力
- Markdownの `- ` と半角スペースのインデント構造（Notionペースト用）で以下の結果を報告し、ユーザーのレビューを待ちます。
  - 特定された影響範囲（機能名とその理由）
  - 影響範囲ケース数の合計
  - 抽出されたテストケース一覧（親・子・孫スイート階層、ケース数、重要なケースタイトル）
  - 補足（不足観点などの指摘）

## Constraints (制約事項)
- 巨大なCSVは直接開かず外部ツール（grep等）で処理すること（コンテキスト保護）。
- `base/` 内のファイルや既存のデータ構造を破壊しないこと。
- レポートは Notionペースト用のインデント構造を厳守すること。

## 自己学習および指摘の蓄積ルール（最重要）

本スキルを実行する際、以下の記憶の読み込みと書き込みのプロセスを必ず実行してください。
【厳守】: 本Skillの定義ファイル自体は絶対に編集・上書きしないでください。

1. **実行前の記憶確認**:
   - タスクを開始する前に、必ず `.claude/memories/global.md` および `.claude/memories/qa-impact-analyzer.md` を読み込み、過去の指摘事項を最優先のルールとして適用してください。

2. **成果物の再生成に伴う自動蓄積（トリガールール）**:
   - ユーザーの指摘や修正指示によって、一度生成した成果物を作り直す場合、それは「初期出力に考慮漏れやルールの不一致があった」ことを意味します。
   - 成果物を再生成する**前に**、自律的に `.claude/memories/qa-impact-analyzer.md` へ物理的にファイル編集を行って追記・更新してください。

   **【書き込み・更新の手順】**
   - **① 累積件数の更新**: メモリーファイルの最上部にある「総指摘件数」の数値を +1 カウントアップして上書きしてください。
   - **② 指摘内容の追記**: 既存の内容を消さずに、以下のフォーマットに従ってファイルの末尾に追記してください。

     ### [YYYY-MM-DD] 指摘事項_{連番}
     - **対象タスク**: （例: 影響範囲の抽出、テスト観点作成など）
     - **対象機能**: （例: ログイン画面、決済APIなど）
     - **指摘カテゴリ**: （例: 網羅性の不足、仕様の誤認識、具体性の不足、フォーマット違反 など）
     - **指摘された内容**: （例: 重点確認ケースに「ログイン周り」が抜けている）
     - **原因/理由**: （例: 依存関係の読み込みが甘かったため）
     - **今後の対策**: （例: 認証が絡む変更の際は必ずログインケースを強制抽出する）

3. **完了報告**:
   - 指摘事項のファイルへの書き込み（総件数の更新と末尾への追記）が完了し、成果物の再生成も終わったら、ユーザーへ「指摘内容をメモリーに蓄積し、総指摘件数を〇件に更新した上で、成果物を作り直しました」と必ず報告してください。
