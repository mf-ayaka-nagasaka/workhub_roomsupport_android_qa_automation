# Skill: unit-test-review-workflow
開発チームの単体テストPRを探すところから、レビュー・`@Qase` 追記・Qase同期までの一連の工程を、対話的に進行管理するオーケストレーターSkillです。各工程の実処理は個別Skillに委譲します。

## Usage
`/unit-test-review-workflow [PR_URL|PR番号]`
例: `/unit-test-review-workflow`
例: `/unit-test-review-workflow https://github.com/bitkey-service/gateaccess-android/pull/42`

- 引数なし: Step 1 でレビュー対象PRを探索します
- `PR_URL` / `PR番号`: 探索をスキップし、そのPRから開始します

## Context / Scope
- **作業リポジトリ（ブランチ操作の対象）**: 本リポジトリ（QAリポジトリ）
- **レビュー対象リポジトリ（読み取り専用）**: `C:\Users\mforce0087\gateaccess-android`（GitHub: `bitkey-service/gateaccess-android`）
- **作業ブランチ**: `unit-test/qa-review`
- **委譲先Skill**: `/check-qa-prs` → `/review-unit-tests` → `/qase-annotation-writer` → `/qase-sync`
- **判定基準書**: `docs/unit_test_review_criteria.md`
- **学習メモリー**: `.claude/memories/global.md` および `.claude/memories/unit-test-review-workflow.md`

## Instructions
あなたはQAリードとして、単体テストレビューの進行管理を行ってください。

【最重要ルール】:
1. **本スキルは進行管理に徹します。** 判定ロジック・レビュー内容・追記内容を本スキル内で独自に実装しないでください。必ず委譲先Skillを呼び出します。
2. **各Stepの完了時に必ず停止し、ユーザーの承認を得てから次へ進んでください。** 全工程を一気に実行してはいけません。
3. **PRコメントの投稿・Qaseへの送信は外向きの操作です。** 委譲先Skillの承認プロセスを省略させないでください。

実行前に `.claude/memories/global.md` と `.claude/memories/unit-test-review-workflow.md` を読み込み、過去の指摘事項を最優先のルールとして適用してください。

---

### Step 0: 作業ブランチの準備

**対象はQAリポジトリ（カレントディレクトリ）です。** gateaccess-android 側では一切ブランチ操作を行いません。

#### 0-1. 作業ツリーの確認

```
git status --porcelain
```

未コミットの変更がある場合は、**処理を中断**して内容を提示し、先にコミットするか退避するようユーザーに確認してください。
**勝手に `git stash` / `git checkout --` を実行してはいけません。**

#### 0-2. ブランチの作成または切り替え

```
git branch --list unit-test/qa-review
```

| 結果 | 操作 |
|---|---|
| 存在する | `git switch unit-test/qa-review` |
| 存在しない | `git fetch origin` の後、`git switch -c unit-test/qa-review main` |

- 既に `unit-test/qa-review` にいる場合は、何もせず「切り替え済み」と報告します。
- 実行結果（作成したのか切り替えたのか、現在のブランチ名）を必ず報告してください。

---

### Step 1: レビュー対象PRの特定

#### 1-1. 引数にPRが指定されている場合
`/check-qa-prs {引数}` を実行し、結果を提示して Step 2 へ進みます。

#### 1-2. 引数なしの場合
`/check-qa-prs` を実行します。

#### 1-3. 対象PRが0件だった場合

**本スキルが受けて、以下の分岐を提示してください。**

```
⚠️ レビュー依頼ベース・テストコード変更ベースのいずれでも対象PRが見つかりませんでした。

レビュー依頼が未設定のPRを手動で指定できます。
対象PRのURL（または番号）を貼り付けてください。

    例: https://github.com/bitkey-service/gateaccess-android/pull/42

対象が無いことを確認して終了する場合は「終了」と入力してください。
```

- URLを受け取ったら `/check-qa-prs {URL}` を実行し、結果を提示して Step 2 へ進みます。
- 「終了」と入力された場合は、作業ブランチをそのままに処理を終了します。
- **URLの形式が不正な場合は、推測で補完せず**、もう一度貼り直すよう依頼してください。

#### 1-4. 対象PRの確定
複数のPRが提示された場合、**どのPRから着手するかをユーザーに選択させてください。**
feature推定が `要確認` のPRは、feature名もあわせて確認してください。

---

### Step 2: レビューの実行

```
/review-unit-tests {PR番号} {feature名}
```

委譲先SkillがPRコメントの投稿承認を求めます。**その承認を本スキルが代行してはいけません。**

投稿完了（または「いいえ」で終了）を確認したら、次へ進んでよいかユーザーに確認します。

> 📌 委譲先SkillのStep -1 で `scenarios_with_viewpoints.md` が更新された場合、その変更は作業ブランチ上に残ります。Step 6 でコミット対象になります。

---

### Step 3: Qaseでのケース採番（人手）

**この工程は自動化できません。** 以下を案内して停止してください。

```
📋 Qase UI でテストケースを作成し、ケースIDを採番してください。

  1. Qase の対象プロジェクトを開く
  2. レビュー済みのテストに対応するケースを作成
  3. 採番されたケースIDを控える

採番が完了したら「完了」と入力してください。
ケースIDが分かっている場合は、そのまま貼り付けてください。
```

- **ケースIDを推測・仮置きしてはいけません。**
- 開発チームが先に採番している場合もあるため、「既に採番済み」と言われた場合はそのIDを使用します。

---

### Step 4: `@Qase` アノテーションの追記

```
/qase-annotation-writer {PR番号} {feature名}
```

委譲先Skillが gateaccess-android のテストコードを編集します。
**編集・コミット・pushの承認は、すべて委譲先Skillのプロセスに従ってください。**

---

### Step 5: Qaseへの同期

```
/qase-sync
```

dry-run の提示 → 承認 → 実行、という委譲先Skillの手順に従います。

> ℹ️ 実行結果とカバレッジの送信は gateaccess-android 側のCIが自動で行います。`results` モードは再送・リカバリ時のみ使用してください。

---

### Step 6: QA成果物の提出

QAリポジトリ側に変更がある場合（Gherkinの更新など）、コミットとPR作成を案内します。

```
git status --porcelain
```

- 変更がある場合: `/end` の実行を案内してください。**本スキル内でコミット・pushを行わないでください。**
- 変更が無い場合: 「QAリポジトリ側の成果物はありません」と報告して終了します。

## Constraints (制約事項)
- **進行管理への限定**: 判定・レビュー・追記のロジックを本スキル内に実装しないこと。必ず委譲先Skillを呼び出すこと。
- **承認の非代行**: 委譲先Skillが求める承認を、本スキルが自動で「はい」と応答しないこと。
- **ブランチ操作の限定**: ブランチ操作はQAリポジトリのみ。gateaccess-android 側でブランチを作成・切り替えしないこと。
- **作業ツリーの保護**: 未コミットの変更がある状態で、`git stash` / `git checkout --` 等の破壊的操作を無断で実行しないこと。
- **工程スキップの禁止**: ユーザーの明示的な指示なく工程を飛ばさないこと。飛ばした場合は完了レポートに明記すること。
- **ID の厳格性**: QaseのケースIDを推測・仮置きしないこと。
- **中断時の状態保持**: 途中で終了する場合も、作業ブランチはそのまま残すこと（自動でmainへ戻さない）。
