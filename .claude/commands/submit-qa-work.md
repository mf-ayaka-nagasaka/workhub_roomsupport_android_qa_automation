# Skill: submit-qa-work
作業内容をコミット・プッシュし、作業者名を冠したタイトルでプルリクエストを作成します。

## Usage
`/submit-qa-work [修正内容（コミットメッセージ）] [作業者名] [レビュー担当者GitHubID（任意）]`

## Context / Scope
- **対象**: カレントブランチの全変更
- **前提条件**: 
  - `main`ブランチ以外の作業ブランチにいること。
  - GitHub CLI (`gh`) が利用可能であること。

## Instructions
あなたはシニアQAエンジニアとして、チームのレビューフローを円滑にするために以下の手順を実行してください。

### 1. 調査・分析 (Investigation)
- `git status` で変更内容を確認。
- `data/*_data/` 内の個人ファイルがステージング（`git add`対象）に含まれていないか、`.gitignore` の設定を再確認してください。

### 2. 実行・加工 (Action)
- **コミット**: 引数の `[修正内容]` をメッセージとして `git add .` および `git commit` を実行。
- **プッシュ**: `git push origin [現在のブランチ名]` を実行。
- **PR作成**: `gh pr create --repo mf-ayaka-nagasaka/workhub_roomsupport_android_qa_automation` コマンドを使用して以下のように作成。
  - **タイトル**: `[作業者名]：[修正内容の要約]`
  - **ボディ**: 修正内容の詳細を記載。
  - **レビュアー**: 第3引数 `[レビュー担当者GitHubID]` がある場合、`--reviewer` オプションで指定。

### 3. レポート・完了報告 (Reporting)
- 生成されたPRのURLを表示。
- **次のステップ案内**: 
  「プルリクエストを作成しました。[レビュー担当者GitHubID（指定があれば）] さんへ、チャット等でレビュー依頼の連絡を行ってください。**レビューが承認されれば、mainブランチへマージされます。**」

## Constraints (制約事項)
- `main` ブランチでの直接操作は絶対に禁止。
- 引数の `[作業者名]` が欠けている場合は、入力を促すこと。

## 自己学習および指摘の蓄積ルール（最重要）

本スキルを実行する際、以下の記憶の読み込みと書き込みのプロセスを必ず実行してください。
【厳守】: 本Skillの定義ファイル自体は絶対に編集・上書きしないでください。

1. **実行前の記憶確認**:
   - タスクを開始する前に、必ず `.claude/memories/global.md` および `.claude/memories/submit-qa-work.md` を読み込み、過去の指摘事項を最優先のルールとして適用してください。

2. **成果物の再生成に伴う自動蓄積（トリガールール）**:
   - ユーザーの指摘や修正指示によって、一度生成した成果物を作り直す場合、それは「初期出力に考慮漏れやルールの不一致があった」ことを意味します。
   - 成果物を再生成する**前に**、自律的に `.claude/memories/submit-qa-work.md` へ物理的にファイル編集を行って追記・更新してください。

   **【書き込み・更新の手順】**
   - **① 累積件数の更新**: メモリーファイルの最上部にある「総指摘件数」の数値を +1 カウントアップして上書きしてください。
   - **② 指摘内容の追記**: 既存の内容を消さずに、以下のフォーマットに従ってファイルの末尾に追記してください。

     ### [YYYY-MM-DD] 指摘事項_{連番}
     - **対象タスク**: （例: 影響範囲の抽出、テスト観点作成など）
     - **対象機能**: （例: ログイン画面、決済APIなど）
     - **指摘カテゴリ**: （例: 網羅性の不足、仕様の誤認識、具体性の不足、フォーマット違反 など）
     - **指摘された内容**: （例: 重点確認ケースに「ログイン周り」が抜けている）
     - **原因/理由**: （例: 依存関係の読み込みが甘かったため）
     - **今後の対策**: （例: 認証が絡む変更の際は必ずログインケースを強制抽出する）

3. **完了報告**:
   - 指摘事項のファイルへの書き込み（総件数の更新と末尾への追記）が完了し、成果物の再生成も終わったら、ユーザーへ「指摘内容をメモリーに蓄積し、総指摘件数を〇件に更新した上で、成果物を作り直しました」と必ず報告してください。
