# Skill: check-qa-prs
QAがレビューすべき単体テスト関連のPRを探し出し、一覧として提示します。レビュー自体は行いません。

## Usage
`/check-qa-prs [--all]`
例: `/check-qa-prs`
例: `/check-qa-prs --all` （レビュー済みのPRも含めて表示）

- 引数なし: 未レビューの対象PRのみ表示します
- `--all`: レビュー済みの対象PRも含めて表示します

## Context / Scope
- **対象リポジトリ**: `bitkey-service/workhubRoomSupport-Android`
- **Gherkin配置先（feature推定に使用）**: `src/test/resources/features/`
- **レビュー実行スキル（本スキルからは自動実行しません）**: `/review-unit-tests`
- **学習メモリー**: `.claude/memories/global.md` および `.claude/memories/check-qa-prs.md`

## Instructions
あなたはQA担当のアシスタントとして、レビュー対象となるPRを特定してください。

【最重要ルール】:
1. **本スキルは読み取り専用です。** PRへのコメント投稿、レビュー登録、ラベル付与、ファイルの変更を一切行わないでください。
2. **レビューを自動で開始しないでください。** 一覧の提示までで必ず停止します。
3. **対象外と判定したPRは一覧に表示しないでください。** 件数のみ報告します。

実行前に `.claude/memories/global.md` と `.claude/memories/check-qa-prs.md` を読み込み、過去の指摘事項（特にfeature推定の誤り）を適用してください。

---

### Step 1: 候補PRの取得

#### 1-1. 主判定（レビュー依頼ベース）
次のコマンドで、自分にレビュー依頼が来ているオープンPRを取得します。

```
gh pr list -R bitkey-service/workhubRoomSupport-Android \
  --search "review-requested:@me" --state open \
  --json number,title,author,headRefName,updatedAt,isDraft
```

#### 1-2. フォールバック判定（テストコード変更ベース）
**1-1 の結果が0件だった場合のみ**、オープンPR全件を取得して次のStepで絞り込みます。

```
gh pr list -R bitkey-service/workhubRoomSupport-Android \
  --state open --limit 30 \
  --json number,title,author,headRefName,updatedAt,isDraft
```

> PR通知（レビュアー指定）の設定が完了するまでは、こちらの経路で拾います。**どちらの経路で取得したかを、必ずレポートの冒頭に明記してください。**

#### 1-3. 使用してはいけない方法
`gh api notifications` は使わないでください。CI失敗通知などのノイズが大量に混ざり、全リポジトリ横断・既読状態にも左右されるため、判定が不安定になります。

---

### Step 2: テストコード変更の有無を判定

各PRについて、変更ファイルの一覧を取得します。

```
gh pr view {number} -R bitkey-service/workhubRoomSupport-Android --json files -q '.files[].path'
```

| 条件 | 判定 |
|---|---|
| `*/src/test/*` を含むファイルがある | ✅ **レビュー対象** |
| `*/src/androidTest/*` のみ | ❌ 対象外（計装テストは本フローの範囲外） |
| `ExampleUnitTest.kt` のみ | ❌ 対象外（テンプレート残骸） |
| テストコードの変更が無い | ❌ 対象外 |
| ドラフトPR（`isDraft: true`） | ❌ 対象外（作業中のため） |

**対象外と判定したPRは一覧に表示しません。** 除外件数のみサマリーで報告してください。

---

### Step 3: レビュー状況の判定

対象PRについて、自分が既にレビューコメントを投稿済みかを確認します。

```
gh pr view {number} -R bitkey-service/workhubRoomSupport-Android \
  --json comments,reviews -q '[.comments[].author.login, .reviews[].author.login] | unique'
```

- 自分のアカウント（`gh api user -q .login` で取得）が含まれていれば **レビュー済み**
- 含まれていなければ **未レビュー**
- 引数に `--all` が無い場合、**レビュー済みのPRは一覧から除外**します（除外件数は報告）

> レビュー済みでもその後にコミットが追加されている場合があります。最終コメント日時より新しいコミットがあれば「**再レビュー推奨**」と表示してください。

---

### Step 4: 対象featureの推定

変更されたテストファイルのパス・クラス名から、対応するGherkinのfeatureディレクトリを推定します。

- `src/test/resources/features/` 配下のディレクトリ一覧を取得し、候補を突き合わせてください。
- 推定できない場合は `要確認` と表示し、**勝手に断定しないでください。**
- 複数のfeatureにまたがる場合は、すべて列挙してください。

---

### Step 5: 一覧の提示

以下の形式で出力し、**必ずここで停止してください。**

```
【QAレビュー対象PR 一覧】
取得日時: {YYYY-MM-DD HH:MM}
判定経路: {レビュー依頼ベース / テストコード変更ベース（フォールバック）}

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

| # | PR | タイトル | 作成者 | テスト変更 | feature推定 | 状況 |
|---|---|---|---|---|---|---|
| 1 | #{n} | {タイトル} | {author} | {n}件 | {feature} | 未レビュー |
| 2 | #{n} | {タイトル} | {author} | {n}件 | 要確認 | 再レビュー推奨 |

■ 除外したPR

| 区分 | 件数 |
|---|---|
| テストコードの変更なし | {n}件 |
| 計装テスト（androidTest）のみ | {n}件 |
| ドラフト | {n}件 |
| レビュー済み | {n}件 |

■ 次のアクション

レビューを実行するには、対象のPR番号とfeature名を指定してください。

    /review-unit-tests {PR番号} {feature名}

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

対象PRが0件だった場合は、除外内訳とあわせて「**現在レビュー対象のPRはありません**」と報告してください。

## Constraints (制約事項)
- **読み取り専用**: PRへのコメント、レビュー登録、ラベル付与、ファイル変更を一切行わないこと。
- **自動実行の禁止**: 一覧を提示したら必ず停止すること。`/review-unit-tests` を続けて自動実行しないこと。
- **対象外の非表示**: 対象外PRは一覧に出さず、件数のみ報告すること。
- **推定の抑制**: featureが特定できない場合は `要確認` とし、断定しないこと。
- **notifications APIの不使用**: `gh api notifications` は判定に使わないこと。
- **コンテキスト保護**: `--json` で必要なフィールドのみ取得すること。PR差分の本文（`gh pr diff`）は本スキルでは読まないこと。
- **判定経路の明示**: 主判定とフォールバックのどちらで取得したかを必ずレポートに明記すること。
