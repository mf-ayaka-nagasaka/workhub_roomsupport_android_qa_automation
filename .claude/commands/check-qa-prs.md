# Skill: check-qa-prs
QAがレビューすべき単体テスト関連のPRを探し出し、一覧として提示します。レビュー自体は行いません。

## Usage
`/check-qa-prs [--all] [PR_URL|PR番号]`
例: `/check-qa-prs`
例: `/check-qa-prs --all` （レビュー済みのPRも含めて表示）
例: `/check-qa-prs https://github.com/bitkey-service/gateaccess-android/pull/42`

- 引数なし: 未レビューの対象PRのみ表示します
- `--all`: レビュー済みの対象PRも含めて表示します
- `PR_URL` / `PR番号`: 探索をスキップし、そのPRだけを判定します（レビュー依頼が未設定のPRを手動で指定する場合に使用）

## Context / Scope
- **対象リポジトリ**: `bitkey-service/gateaccess-android`
- **Gherkin配置先（feature推定に使用）**: `src/test/resources/features/`
- **レビュー実行スキル（本スキルからは自動実行しません）**: `/review-unit-tests`
- **学習メモリー**: `.claude/memories/global.md` および `.claude/memories/check-qa-prs.md`

## Instructions
あなたはQA担当のアシスタントとして、レビュー対象となるPRを特定してください。

【最重要ルール】:
1. **本スキルは読み取り専用です。** PRへのコメント投稿、レビュー登録、ラベル付与、ファイルの変更を一切行わないでください。
2. **レビューを自動で開始しないでください。** 一覧の提示までで必ず停止します。
3. **対象外と判定したPRは一覧に表示しないでください。** 件数のみ報告します。

実行前に `.claude/memories/global.md` と `.claude/memories/check-qa-prs.md` を読み込み、過去の指摘事項（特にfeature推定の誤り）を適用してください。

---

### Step 1: 候補PRの取得

#### 1-0. PR URL / PR番号が引数で指定されている場合
引数にPRのURLまたは番号が含まれている場合、**1-1 / 1-2 の探索は行いません。**

- URLから `{owner}/{repo}` とPR番号を抽出します。
- 抽出したリポジトリが `bitkey-service/gateaccess-android` と異なる場合は、**処理を中断**し、対象外のリポジトリである旨を報告してください。
- 指定されたPRのみを対象として Step 2 以降を実行します。
- 判定経路は「**URL直接指定**」としてレポートに明記してください。
- この経路では、対象外と判定された場合も**理由を明示して報告**してください（ユーザーが意図して指定したPRのため、黙って除外しない）。

#### 1-1. 主判定（レビュー依頼ベース）
次のコマンドで、自分にレビュー依頼が来ているオープンPRを取得します。

```
gh pr list -R bitkey-service/gateaccess-android \
  --search "review-requested:@me" --state open \
  --json number,title,author,headRefName,updatedAt,isDraft
```

#### 1-2. フォールバック判定（テストコード変更ベース）
**1-1 の結果が0件だった場合のみ**、オープンPR全件を取得して次のStepで絞り込みます。

```
gh pr list -R bitkey-service/gateaccess-android \
  --state open --limit 30 \
  --json number,title,author,headRefName,updatedAt,isDraft
```

> PR通知（レビュアー指定）の設定が完了するまでは、こちらの経路で拾います。**どちらの経路で取得したかを、必ずレポートの冒頭に明記してください。**

#### 1-3. 使用してはいけない方法
`gh api notifications` は使わないでください。CI失敗通知などのノイズが大量に混ざり、全リポジトリ横断・既読状態にも左右されるため、判定が不安定になります。

---

### Step 2: テストコード変更の有無を判定

各PRについて、変更ファイルの一覧を取得します。

```
gh pr view {number} -R bitkey-service/gateaccess-android --json files -q '.files[].path'
```

| 条件 | 判定 |
|---|---|
| `*/src/test/*` を含むファイルがある | ✅ **レビュー対象** |
| `*/src/androidTest/*` のみ | ❌ 対象外（計装テストは本フローの範囲外） |
| `ExampleUnitTest.kt` のみ | ❌ 対象外（テンプレート残骸） |
| テストコードの変更が無い | ❌ 対象外 |
| ドラフトPR（`isDraft: true`） | ❌ 対象外（作業中のため） |

**対象外と判定したPRは一覧に表示しません。** 除外件数のみサマリーで報告してください。

---

### Step 3: レビュー状況の判定

対象PRについて、自分が既にレビューコメントを投稿済みかを確認します。

```
gh pr view {number} -R bitkey-service/gateaccess-android \
  --json comments,reviews -q '[.comments[].author.login, .reviews[].author.login] | unique'
```

- 自分のアカウント（`gh api user -q .login` で取得）が含まれていれば **レビュー済み**
- 含まれていなければ **未レビュー**
- 引数に `--all` が無い場合、**レビュー済みのPRは一覧から除外**します（除外件数は報告）

> レビュー済みでもその後にコミットが追加されている場合があります。最終コメント日時より新しいコミットがあれば「**再レビュー推奨**」と表示してください。

---

### Step 4: 対象feature・シナリオの推定

#### 4-1. featureの推定

変更されたテストファイルのパス・クラス名から、対応するGherkinのfeatureディレクトリを推定します。

- `src/test/resources/features/` 配下のディレクトリ一覧を取得し、候補を突き合わせてください。
- 推定できない場合は `要確認` と表示し、**勝手に断定しないでください。**
- 複数のfeatureにまたがる場合は、すべて列挙してください。

#### 4-2. 対象シナリオの推定

**開発チームからのレビュー依頼はシナリオ単位で来ます。** テストファイルからQaseケースIDを拾い、`/review-unit-tests` に渡せる形にします。

変更されたテストファイルの中身を取得し、以下の順で検索してください。

```
gh pr diff {number} -R bitkey-service/gateaccess-android
```

| 優先 | 探す対象 | 例 |
|---|---|---|
| 1 | `@Qase` アノテーションの `id` | `@Qase(id = 3, ...)` → `RSA-3` |
| 2 | KDoc・コメント内のケースID | `/** RSA-3: 単数組織に... */` → `RSA-3` |

- 拾えたIDは、`src/test/resources/features/{feature}/scenarios_with_viewpoints.md` に実在するか突き合わせてください。
- **拾えない場合・実在しない場合は `要確認` と表示し、勝手に断定しないでください。**
- 複数のケースIDにまたがる場合は、すべて列挙してください。

> ⚠️ 開発チームがケースIDを書いていないケースもあります。`要確認` は異常ではありません。その場合はユーザーがシナリオを指定します。

以下の形式で出力し、**必ずここで停止してください。**

```

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 除外したPR

| 区分 | 件数 |
|---|---|

    /review-unit-tests {PR番号} {feature名} {シナリオ}

シナリオ推定が `要確認` の場合は、対象シナリオをQaseケースID（`RSA-3` 等）
またはシナリオ名で指定してください。省略するとfeature全体が対象になります。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

#### 対象PRが0件だった場合

除外内訳とあわせて、以下の形式で報告して停止してください。

```
⚠️ 現在レビュー対象のPRはありません。

■ 除外したPR
（除外内訳の表）

■ 次のアクション

レビュー依頼が未設定のPRを手動で確認する場合は、PRのURLを指定して再実行してください。

    /check-qa-prs https://github.com/bitkey-service/gateaccess-android/pull/42
```

**本スキル内でURLの入力を待つ対話ループは持ちません。** 案内の提示までで停止します。

## Constraints (制約事項)
- **読み取り専用**: PRへのコメント、レビュー登録、ラベル付与、ファイル変更を一切行わないこと。
- **自動実行の禁止**: 一覧を提示したら必ず停止すること。`/review-unit-tests` を続けて自動実行しないこと。
- **対象外の非表示**: 対象外PRは一覧に出さず、件数のみ報告すること。
- **推定の抑制**: feature・シナリオが特定できない場合は `要確認` とし、断定しないこと。
- **notifications APIの不使用**: `gh api notifications` は判定に使わないこと。
- **コンテキスト保護**: `--json` で必要なフィールドのみ取得すること。PR差分の本文（`gh pr diff`）を読むのは、**Step 4-2 のケースID抽出に限る**こと。レビュー目的でテストロジックを精査しないこと（それは `/review-unit-tests` の責務）。
- **判定経路の明示**: 主判定・フォールバック・URL直接指定のどの経路で取得したかを必ずレポートに明記すること。
- **URL指定時の透明性**: URL直接指定の経路では、対象外と判定した場合も理由を明示して報告すること（件数のみの報告にしない）。
