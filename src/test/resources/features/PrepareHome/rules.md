## ルールの洗い出しと正常系・異常系の分類

### 機能名: 起動準備とホーム画面表示
**機能概要:** 設定の読み込みが完了して起動準備画面に到達した後、進行中であることを示しながら、設定画面のタブレット名・設置空間に不備がないかを確認する。不備があれば設定画面へ誘導し、不備がなければ予約認証モードで予約データを初回取得して、完了後（またはタイムアウト後）にホーム画面を表示する。

**起動準備の処理順序:** ①進行表示の開始 → ②共通セットアップ（Firestoreリスナーの配線） → ③設定の不備確認 → ④並列データ取得 → ⑤ホーム画面へ遷移。③で不備が見つかった場合のみ、④以降は実行されない。

**責務の切り分け:** 以下は本機能の対象外とし、記載のチケットで検証する（`_master/feature-map.html` の決定台帳を参照）。

| 対象外とする処理 | 移管先のチケット | 台帳 |
| :--- | :--- | :--- |
| 端末の登録状態・初期設定の完了状態の判定、組織→タブレットID→端末設定の解決 | 設定値の読み込みが行える | #1〜#3 |
| 利用不可・利用時間外の表示 | 利用不可・利用時間外を表示できる | #5 |
| 起動準備中に実行される顔情報の修復 | 顔の特徴量を同期できる | #6 |
| オフライン起動時の振る舞い | オフライン時のフォールバックを設計・検討できる | #7 |

---

### ルール①: 起動準備の実行中は進行中であることが示され、利用者の操作を受け付けない
**推奨テスト階層:** Presentation Unitテスト (JVM / Turbine)
**割り振り理由:** 進行表示の開始・継続・解除はViewModelの状態変化であり、実機描画なしで検証できるため。

| 対象 | 状況 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 起動準備画面 | 画面の表示直後 | 🟢 正常系：起動準備画面に到達する | 「設定を反映しています」という進行中の表示が現れる |
| 起動準備画面 | 並列データ取得の実行中 | 🟢 正常系：起動準備の処理が続いている | 進行中の表示が維持され、操作できる要素は表示されない |
| 起動準備画面 | ホーム画面への遷移時 | 🟢 正常系：起動準備が完了する | 進行中の表示が解除される |

---

### ルール②: 設定画面のタブレット名・設置空間に不備があると、起動準備は中断され設定画面へ誘導される
**推奨テスト階層:** Application Unitテスト (JVM)
**割り振り理由:** 設定の不備判定とその後の分岐（設定画面への誘導／起動準備の継続）を、外部依存をFakeに差し替えて通しで検証する必要があるため。

> 不備を検出して設定画面へ送り返すのは本機能の責務（台帳 #4）。タブレット名・設置空間を入力するのは初期設定と設定画面の責務であり、誘導された後の設定画面の挙動（キャンセルが提供されないこと）は「管理者が予約認証の設定を変更できる」で検証する。

| 対象 | 設定の状態 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 端末 | タブレット名・設置空間ともに設定済み | 🟢 正常系：設定に不備がない状態で起動準備を開始する | 設定画面へは遷移せず、並列データ取得（ルール③・④）が開始される |
| 端末 | タブレット名が未設定（空文字） | 🔴 異常系：タブレット名が空の状態で起動準備を開始する | 予約データの取得は行われず、設定画面へ遷移して設定を促す |
| 端末 | 設置空間が未設定（未選択または空） | 🔴 異常系：設置空間が未設定の状態で起動準備を開始する | 予約データの取得は行われず、設定画面へ遷移して設定を促す |

---

### ルール③: 起動準備の処理が60秒を超えても、中断されずホーム画面へ進む
**推奨テスト階層:** Application Unitテスト (JVM)
**割り振り理由:** 制限時間の超過をFakeで再現し、超過後も後続の遷移が行われることを通しで検証する必要があるため。

> 予約データ待ちの10秒（ルール④）とは別に、起動準備の処理全体に60秒の制限時間がある。超過しても失敗としては扱われず、記録を残したうえで処理を続行する。

| 対象 | 状況 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 起動準備 | 60秒以内にすべての準備が完了 | 🟢 正常系：並列データ取得が時間内に完了する | そのままホーム画面へ遷移する |
| 起動準備 | 60秒を超過 | 🟡 例外系：並列データ取得が60秒を超えても完了しない | エラーは表示されず、中断もされずにホーム画面へ遷移する |

---

### ルール④: 予約認証モードでは常に予約データ準備が実行され、初回取得は最大10秒待機してタイムアウトしてもホーム画面へ進む
**推奨テスト階層:** Application Unitテスト (JVM)
**割り振り理由:** 予約一覧・空間ステータス・予約設定・利用不可時間の初回到着待機とタイムアウト分岐を含む一連のユースケースフローであり、タイムアウトをFakeで再現して通しで検証する必要があるため。

| 対象 | 状況 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| タブレット | 予約認証モード | 🟢 正常系：起動準備を開始する | 予約データ準備が実行され、Firestoreリスナーが配線されて予約一覧・空間ステータス・予約設定・利用不可時間の取得が始まる |
| 予約データ | 10秒以内に到着 | 🟢 正常系：予約データが時間内に揃う | 取得したデータでホーム画面へ遷移する |
| 予約データ | 10秒待っても未到着 | 🟡 例外系：予約データの初回到着を最大10秒待っても揃わない | タイムアウトしてホーム画面へ進む（後続はリスナーで反映される＝ルール⑤） |
| 予約データ | 予約一覧・空間ステータス・予約設定・利用不可時間の4種のうち一部のみ10秒以内に到着 | 🟡 例外系（要確認）：部分到着のままタイムアウト | 要確認（赤カード参照）※「予約データが揃う」の定義（全種待ちか一部可か）と部分到着時のホーム画面への反映内容が未確定 |

---

### ルール⑤: 反映された予約データの状態に応じて、ホーム画面の表示状態が決まる
**推奨テスト階層:** Application Unitテスト (JVM)
**割り振り理由:** 予約データの状態（なし／未入室／入室済み）に応じた表示分岐を、Fakeの予約データに差し替えて検証するため。

| 対象 | 予約データの状態 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| ホーム画面 | 予約データなし | 🟢 正常系：対象空間に予約がない状態で表示する | 空室状態で表示される（背景色=白、ボタン「今すぐ入室」） |
| ホーム画面 | 予約あり・未入室 | 🟢 正常系：予約はあるがまだ入室していない状態で表示する | 待機中状態で表示される（背景色=オレンジ、ボタン「入室する」） |
| ホーム画面 | 予約あり・入室済み | 🟢 正常系：入室済みの予約がある状態で表示する | 使用中状態で表示される（背景色=赤ピンク、ボタン「退室する」） |
| ホーム画面 | ルール④でタイムアウトし予約データ未取得のまま表示 | 🟡 例外系：ホーム画面の表示後にリスナー経由で予約データが遅れて届く | 画面遷移なしにその場で背景色・ボタンラベル等が予約状態に応じて自動更新される |
| ホーム画面 | 予約あり・入室可能時間の閾値未到達 | 🟢 正常系：入室可能時間より前 | 空室状態で表示される |
| ホーム画面 | 予約あり・入室可能時間の閾値到達直後 | 🟢 正常系：入室可能時間に到達した直後 | 待機中状態で表示される（背景色=オレンジ、ボタン「入室する」）※境界値テスト対象 |

※入室可能時間の閾値前後は業務ルールとして表示状態そのものが切り替わるため境界値テストの対象とする（Firestore取得待ちの10秒閾値とは性質が異なり、そちらは境界値テスト対象外と判断済み）。
