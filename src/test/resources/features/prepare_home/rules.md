## ルールの洗い出しと正常系・異常系の分類

### 機能名: 起動準備とホーム表示
**機能概要:** ログイン・組織選択完了後、組織→タブレットID→端末設定(Thing)を解決し、未登録・未設定なら適切な画面へ誘導する。登録済み・設定完了であれば、予約認証モードで予約データを初回取得し、完了後（またはタイムアウト後）にホーム画面を表示する。

---

### ルール①: 端末の登録・設定状態に応じて、ホームへ進めるか他画面へ誘導されるかが決まる
**推奨テスト階層:** Application Unitテスト (JVM)
**割り振り理由:** 組織→タブレットID→Thing取得という一連の解決フローとその分岐を、外部依存をFakeに差し替えて通しで検証する必要があるため。

**チェック順序:** ①Thing存在確認 → ②settingState確認 → ③端末名/設置空間確認。前段が未達の場合、後段の状態に関わらず前段の遷移先が優先される（順次評価のガード節であり、複数条件の同時成立は発生しない）。

| 対象 | 端末の状態 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 端末 | 登録済み・初期設定完了・端末名/空間設定済み | 🟢 正常系：組織・タブレットID・Thingが解決できる | 起動準備が継続され、予約データ準備（ルール②）へ進む |
| 端末 | Thingが存在しない（未登録） | 🟡 例外系：端末未登録の状態で起動準備を開始する | インストール確認ダイアログが表示され、「新規設置」または「再設置」を選択できる ※1 |
| 端末 | 未登録・ダイアログ表示中 | 🟢 正常系：「新規設置」を選択する | 初期設定ウィザードへ遷移する |
| 端末 | 未登録・ダイアログ表示中 | 🟢 正常系：「再設置」を選択する | 再インストール画面へ遷移する |
| 端末 | settingStateがcompletedでない | 🟡 例外系：初期設定が未完了の状態で起動準備を開始する | 初期設定ウィザードへ遷移する |
| 端末 | 端末名または設置空間が未設定 | 🔴 異常系：端末名または空間が未設定の状態で起動準備を進める | 設定画面へ遷移して設定を促す |
| 端末 | 起動準備中に組織取得APIがエラーを返す | 🔴 異常系（要確認）：組織情報取得APIエラー | 要確認（赤カード参照）※ログイン画面へ戻るかリトライ提供か未確定 |
| 端末 | 起動準備中にThing取得APIがエラーを返す | 🔴 異常系（要確認）：Thing情報取得APIエラー | 同上 |
| 端末 | 起動準備中に認証トークンが失効する | 🔴 異常系（要確認）：認証トークン失効 | 同上 |

※1 開発シナリオでは「登録確認ダイアログ」「登録または再インストール」と表現されているが、仕様書(`setting-loader_feature.md`)の正式名称は「インストール確認ダイアログ」（タイトル「設置方法を選択してください」）、選択肢は「新規設置」「再設置」。用語のすり合わせが必要（赤カード参照）。

---

### ルール②: 予約認証モードでは常に予約データ準備が実行され、初回取得は最大10秒待機してタイムアウトしてもホームへ進む
**推奨テスト階層:** Application Unitテスト (JVM)
**割り振り理由:** 予約一覧・空間ステータス・予約設定・利用不可時間の初回到着待機とタイムアウト分岐を含む一連のユースケースフローであり、タイムアウトをFakeで再現して通しで検証する必要があるため。

| 対象 | 状況 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| タブレット | 予約認証モード | 🟢 正常系：起動準備を開始する | `prepareReservationIfNeeded()`が実行され、Firestoreリスナーが配線されて予約一覧・空間ステータス・予約設定・利用不可時間の取得が始まる |
| 予約データ | 10秒以内に到着 | 🟢 正常系：予約データが時間内に揃う | 取得したデータでホーム画面へ遷移する |
| 予約データ | 10秒待っても未到着 | 🟡 例外系：予約データの初回到着を最大10秒待っても揃わない | タイムアウトしてホーム画面へ進む（後続はリスナーで反映される＝ルール③） |
| 予約データ | 予約一覧・空間ステータス・予約設定・利用不可時間の4種のうち一部のみ10秒以内に到着 | 🟡 例外系（要確認）：部分到着のままタイムアウト | 要確認（赤カード参照）※「予約データが揃う」の定義（全種待ちか一部可か）と部分到着時のホーム反映内容が未確定 |

---

### ルール③: 反映された予約データの状態に応じて、ホーム画面の表示状態が決まる
**推奨テスト階層:** Application Unitテスト (JVM)
**割り振り理由:** 予約データの状態（なし／未入室／入室済み）に応じた表示分岐を、Fakeの予約データに差し替えて検証するため。

| 対象 | 予約データの状態 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| ホーム画面 | 予約データなし | 🟢 正常系：対象空間に予約がない状態で表示する | 空室状態で表示される（背景色=白、ボタン「今すぐ入室」） |
| ホーム画面 | 予約あり・未入室 | 🟢 正常系：予約はあるがまだ入室していない状態で表示する | 待機中状態で表示される（背景色=オレンジ、ボタン「入室する」） |
| ホーム画面 | 予約あり・入室済み | 🟢 正常系：入室済みの予約がある状態で表示する | 使用中状態で表示される（背景色=赤ピンク、ボタン「退室する」） |
| ホーム画面 | ルール②でタイムアウトし予約データ未取得のまま表示 | 🟡 例外系：ホーム表示後にリスナー経由で予約データが遅れて届く | 画面遷移なしにその場で背景色・ボタンラベル等が予約状態に応じて自動更新される |
| ホーム画面 | 予約あり・入室可能時間の閾値未到達 | 🟢 正常系：入室可能時間より前 | 空室状態で表示される |
| ホーム画面 | 予約あり・入室可能時間の閾値到達直後 | 🟢 正常系：入室可能時間に到達した直後 | 待機中状態で表示される（背景色=オレンジ、ボタン「入室する」）※境界値テスト対象 |
| ホーム画面 | 利用不可時間中 | 🟢 正常系：利用不可時間中の空間 | 「利用時間外」状態で表示される（背景色=紺色、ボタンなし、「利用時間外」ラベル表示） |

※入室可能時間の閾値前後は業務ルールとして表示状態そのものが切り替わるため境界値テストの対象とする（Firestore取得待ちの10秒閾値とは性質が異なり、そちらは境界値テスト対象外と判断済み）。
