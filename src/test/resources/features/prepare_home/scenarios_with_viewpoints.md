# language: ja
機能: 起動時に予約データを準備してホームを表示できる
  アプリ起動後、端末の登録・設定状態を確認し、予約データを含む各種データの初回到着を待機したうえでホーム画面(MainMenu)へ自動遷移する

  背景:
    前提 ログイン・組織選択が完了している

  # ────────────────────────────────────────
  # ルール①: 端末の登録・設定状態に応じて、ホームへ進めるか他画面へ誘導されるかが決まる
  # ────────────────────────────────────────

  # @TestLevel: ApplicationUnit (JVM)
  # 🟢 正常系：すべて正常な状態での起動
  シナリオ: 登録・初期設定・端末名/空間設定がすべて完了している場合はホームへ進める
    前提 会議室タブレットは登録済みであり、初期設定ウィザードが完了しており、設定画面上のタブレット名と設置空間が設定されている
    もし 会議室タブレットが起動準備を開始する
    ならば 予約データを含む起動準備を経てホーム画面(MainMenu)が表示される

  # @TestLevel: ApplicationUnit (JVM)
  # 🔴 異常系：端末が未登録
  シナリオ: 端末が未登録の場合は登録確認ダイアログが表示される
    前提 会議室タブレットに対応する端末登録情報(Thing)が存在しない
    もし 会議室タブレットが起動準備を開始する
    ならば 登録確認ダイアログが表示される
    かつ 登録または再インストールを選択できる

  # @TestLevel: ApplicationUnit (JVM)
  # 🔴 異常系：初期設定ウィザードが未完了
  シナリオ: 初期設定ウィザードが未完了の場合は初期設定ウィザードへ遷移する
    前提 会議室タブレットは登録済みだが、初期設定ウィザード（認証方式選択・テンプレート適用等）が完了していない
    もし 会議室タブレットが起動準備を開始する
    ならば 初期設定ウィザードへ遷移する

  # @TestLevel: ApplicationUnit (JVM)
  # 🔴 異常系：ウィザード完了済みだが端末名/設置空間が未設定
  シナリオ: 初期設定は完了しているが端末名または設置空間が未設定の場合は設定画面へ遷移する
    前提 会議室タブレットは初期設定ウィザードを完了しているが、設定画面上のタブレット名または設置空間が未設定である
    もし 会議室タブレットが起動準備を進める
    ならば 設定画面へ遷移し、設定入力を促される

  # @TestLevel: ApplicationUnit (JVM)
  # 🟡例外系：ネットワーク未接続状態で起動した場合
  シナリオ: ネットワーク未接続状態で起動した場合は読み込み画面のまま進めない
    前提 会議室タブレットは登録・初期設定・端末名/空間設定がすべて完了しているが、ネットワークに接続できていない
    もし 会議室タブレットがオフライン状態で起動準備を開始する
    ならば エラー表示なく、読み込み画面が表示されたままホーム画面(MainMenu)へは遷移しない

    # 📐 観点：オフライン状態
    前提 タブレットがWiFi OFFの状態で起動準備を開始する
    ならば エラー表示なく読み込み画面のままホーム画面へは遷移しない

    前提 タブレットが機内モードの状態で起動準備を開始する
    ならば エラー表示なく読み込み画面のままホーム画面へは遷移しない

    前提 タブレットがSIM無効の状態で起動準備を開始する
    ならば エラー表示なく読み込み画面のままホーム画面へは遷移しない

    前提 タブレットのネットワーク接続が不安定な状態で起動準備を開始する
    ならば エラー表示なく読み込み画面のままホーム画面へは遷移しない

    前提 タブレットがDNS解決に失敗する状態で起動準備を開始する
    ならば エラー表示なく読み込み画面のままホーム画面へは遷移しない

  # ────────────────────────────────────────
  # ルール②: 予約データの初回取得を待機し、時間内に揃わなくてもホームへ進める
  # ────────────────────────────────────────

  # @TestLevel: ApplicationUnit (JVM)
  # 🟢 正常系：予約データが時間内に揃う
  シナリオ: 予約データが10秒以内に揃った場合は反映された状態でホームが表示される
    前提 会議室タブレットは登録・初期設定・端末名/空間設定がすべて完了しており、当該スペースに予約が1件登録されている
    もし 会議室タブレットが起動準備を開始し、予約データの初回取得が10秒以内に完了する
    ならば 予約データが反映された状態でホーム画面(MainMenu)が表示される

  # @TestLevel: ApplicationUnit (JVM)
  # 🟡例外系：予約データが時間内に揃わない
  シナリオ: 予約データが10秒待っても揃わない場合でもタイムアウトしてホームへ進み、後からリスナー通知で自動反映される
    前提 会議室タブレットは登録・初期設定・端末名/空間設定がすべて完了している
    もし 会議室タブレットが起動準備を開始し、予約データの初回取得を最大10秒待っても完了しない
    ならば エラー表示なく、空室状態のままホーム画面(MainMenu)が表示される
    かつ その後Firestoreリスナーが予約データを受信すると、画面遷移なしにホームの表示が予約反映済みの状態へ自動的に切り替わる

  # ────────────────────────────────────────
  # ルール③: 反映された予約データの状態に応じてホーム画面の表示状態が決まる
  # ────────────────────────────────────────

  # @TestLevel: ApplicationUnit (JVM)
  # 🟢 正常系：予約なしでホームが表示される
  シナリオ: 予約データが存在しない場合はホームが空室状態で表示される
    前提 会議室タブレットは登録・初期設定・端末名/空間設定がすべて完了しており、当該スペースに予約が0件である
    もし 会議室タブレットが起動準備を開始し、予約データの初回取得が完了する
    ならば ホーム画面(MainMenu)が空室状態で表示される

  # @TestLevel: ApplicationUnit (JVM)
  # 🟢 正常系：予約あり・未入室でホームが表示される
  シナリオ: 予約データが未入室の状態で反映された場合はホームが入室待ち状態で表示される
    前提 会議室タブレットは登録・初期設定・端末名/空間設定がすべて完了しており、当該スペースに未入室の予約が1件登録されている
    もし 会議室タブレットが起動準備を開始し、予約データの初回取得が完了する
    ならば ホーム画面(MainMenu)が入室待ち状態で表示される

  # @TestLevel: ApplicationUnit (JVM)
  # 🟢 正常系：予約あり・入室済みでホームが表示される
  シナリオ: 予約データが入室済みの状態で反映された場合はホームが利用中状態で表示される
    前提 会議室タブレットは登録・初期設定・端末名/空間設定がすべて完了しており、当該スペースに入室済みの予約が1件登録されている
    もし 会議室タブレットが起動準備を開始し、予約データの初回取得が完了する
    ならば ホーム画面(MainMenu)が利用中状態で表示される

    もし 会議室タブレットが起動準備を開始する
