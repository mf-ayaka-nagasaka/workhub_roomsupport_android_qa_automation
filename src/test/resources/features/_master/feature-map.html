このマップの使い方

Gherkinシナリオを作り始める前に、責務を決める

  1. 決定台帳を読む … 着手するチケットが、すでに決まっている境界に触れていないか確認する。
  2. 受け入れ条件を分解する … 1項目ずつに切り分ける。1項目に複数の分岐が入っていることが多い。
  3. 各項目の担当を判定する … 仕様書とソースで「その処理がどの画面にあるか」を確かめ、対象／対象外／要判断に仕分ける。
  4. 重なる項目を論点として提示し、合意する … 既存チケットと重なるものは必ず確認を取る。
  5. 決定台帳に追記する … 決まった内容と根拠をこのマップへ書き戻す。

常時認証モードに関する画面・処理は、このマップの対象外です。本プロダクトは予約認証モードのみを対象とするため、常時認証画面（AlwaysCameraAuthenticationView）とアイドル画面（IdlingRoute・常時認証画面からのみ遷移）は載せていません。

ここまで終えてから、ルールの洗い出し → Gherkin作成 → 観点抽出 へ進みます。チケット完了時には、一覧の状態と成果物の欄も更新します。決めきれなかった論点は「赤カード」として台帳に残し、開発チームとの確認に持ち込みます。

責務の境界線（決定台帳）

「どちらのチケットで見るのか」で迷った論点と、その決定・根拠を残す場所です。新しいチケットに着手するときは、まずここを読んでください。チケットを選ぶと、そのチケットに関係する論点だけが残ります。

責務の分類はQAが先に行い、リファインメントで合意します。「決定」列は合意後の割り当て、「決定日」列は合意した日です。判断を支える詳細（実装の分析・代替案・残課題）は各機能の rules.md の注記・赤カードに置きます。
