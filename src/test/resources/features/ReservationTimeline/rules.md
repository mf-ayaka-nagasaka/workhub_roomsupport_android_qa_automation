## ルールの洗い出しと正常系・異常系の分類

### 機能名: 当日の予約タイムライン表示
**機能概要:** ホーム画面の下部に当日0時から25時（翌日1時）までのタイムラインを表示し、設置空間の予約を時間帯のバーとして並べる。現在時刻の位置が分かるよう一定間隔で自動スクロールし、予約バーをタップすると公開範囲に応じた詳細を確認できる。

**合否の判定:** タイムラインの検証は、目盛りとの位置関係・バーの有無・ダイアログに表示される文言で行う。背景色・バーの濃淡・現在時刻バーの色など**色による表現は検証対象としない**（⑦「部屋の予約状況をホーム画面に表示できる」で決めた、状態の合否は色ではなく文言で判定する方針に合わせる）。

**責務の切り分け:** 以下は本機能の対象外とし、記載のチケットで検証する（`_master/feature-map.html` の決定台帳を参照）。

| 対象外とする処理 | 移管先のチケット | 台帳 |
| :--- | :--- | :--- |
| 部屋の状態（空室・入室待ち・利用中・利用不可）の判定 | 部屋の予約状況をホーム画面に表示できる／利用不可・利用時間外を表示できる | #24 |
| 「予約削除」ボタンの**可否判定の中身**（キャンセル可能期間・サードプレイスのキャンセルポリシー・削除ボタンの表示設定・顔認証オプションの有効状態） | 予約をキャンセル・削除できる | #25 |
| 予約削除の**実行**とその成否・エラー表示 | 予約をキャンセル・削除できる | #25 |
| ホーム画面本体の参加者情報エリアの表示 | 予約の参加者情報を表示できる | #24 |
| 当日予約データのリアルタイム同期そのもの | 起動時に予約データを準備してホームを表示できる／部屋の予約状況をホーム画面に表示できる | — |
| 端末設定「予約情報の表示」の変更 | 管理者が予約認証の設定を変更できる | — |
| 色による状態表現（背景色・バーの濃淡・現在時刻バーの色） | — | 検証対象外 |

> ※ 同じ時刻に重なる予約は発生しない前提とする（⑦で合意済み）。

---

### ルール①: タイムラインには、表示範囲に重なる予約だけが時間帯のバーとして表示される

> バーの開始位置は**データ上の予約開始時刻**で決まり、入室した実際の時刻は影響しない。一方、**終了位置は退室済みなら実際の退室時刻**になる。
> 表示するかどうかは、**当日 0:00 から 25:00（翌日1時）までの表示範囲と重なるか**で決まる。重なりが無い予約は表示されない。

| 対象 | 予約の期間 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 設置空間 | 当日に収まる | 🟢 正常系：当日 10:00〜11:00 の予約が1件ある | 10時の目盛りから11時の目盛りまでを占めるバーが表示される |
| 設置空間 | 前日から当日へ続く | 🟢 正常系：前日 23:00〜当日 1:00 の予約がある | 0時の目盛りより手前から1時の目盛りまでのバーが表示される |
| 設置空間 | 当日から翌日へ続く | 🟢 正常系：当日 23:00〜翌日 1:00 の予約がある | 23時の目盛りから右端（25時）の目盛りまでのバーが表示される |
| 設置空間 | 前日から翌日へ続く | 🟢 正常系：前日 23:00〜翌日 1:00 の予約があり、現在時刻がその期間内 | 0時の手前から右端（25時）の目盛りまで、1日全体を覆うバーが表示される |
| 設置空間 | 翌日だが表示範囲の内側 | 🟢 正常系：翌日 0:30〜1:00 の予約だけがある | 24時の目盛りと右端（25時）の目盛りの中間から右端までのバーが表示される |
| 設置空間 | 表示範囲に重ならない（手前） | 🔴 異常系：前日 23:00〜当日 0:00（0時ちょうどに終了）の予約だけがある | バーは表示されない |
| 設置空間 | 表示範囲に重ならない（先） | 🔴 異常系：翌日 1:00〜2:00（25時ちょうどに開始）の予約だけがある | バーは表示されない |
| 設置空間 | 予定より遅れて入室 | 🟡 例外系：10:00〜11:00 の予約に 10:20 に入室した | バーの開始位置は 10時のまま変わらない |
| 設置空間 | 予定より早く退室 | 🟡 例外系：10:00〜11:00 の予約に入室し、10:40 に退室した | バーの終わりが 10時40分の位置まで縮む |
| 予約バーの時刻ラベル | 画面幅より長い | 🟢 正常系：前日 23:00〜当日 11:00 の予約を表示し、バーの左端が画面の外に出るまで横にスクロールする | 開始時刻と終了時刻が画面の左端に留まり、バーの内側に収まる範囲で表示され続ける（時刻が表示されない短いバーは対象外） |
| 設置空間 | 予約なし | 🟢 正常系：当日に関わる予約が1件も無い | バーは表示されず、目盛りと現在時刻バーだけが表示される |
| 設置空間 | 当日に多数 | 🟡 例外系：当日に想定最大件数の予約がある（件数は `docs/quality_criteria/workhub_roomsupport/criteria.md` の `PE-07` を参照） | すべてのバーが、それぞれの予約時刻の目盛りに一致する位置と長さで描画される |

---

### ルール②: タイムラインには当日の目盛り・現在時刻・日付が表示される

> 日付が変わったときの更新は専用の処理によるものではなく、自動スクロールのための状態更新（10秒間隔）をきっかけに再描画されることで起きる。

| 対象 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- |
| 時間目盛り | 🟢 正常系：タイムラインを表示する | 左端から「0」「1」…「23」と並び、続いて24時に相当する「0」、25時に相当する「1」が並ぶ |
| 現在時刻バー | 🟢 正常系：現在時刻が 10:30 である | 10時と11時の目盛りの中間の位置にバーが表示される |
| 日付ラベル | 🟢 正常系：当日が 11月4日（火）である | 「11/4 (火)」が表示される |
| 日付ラベル・予約バー | 🟡 例外系：11月4日 23:50 にタイムラインを表示したまま 0:00 を跨ぐ | 遅くとも約10秒以内に日付ラベルが「11/5 (水)」へ変わり、11月4日だけの予約のバーが消えて、11月5日の予約のバーが表示される |

---

### ルール③: 予約バーには開始・終了時刻が表示されるが、バーが短いときは表示されない

> 時刻が表示されなくなる境界は**予約時間 25分30秒**。これより短い予約ではバーだけが表示される。

| 対象 | 予約時間 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 予約バー | 30分（代表例） | 🟢 正常系：当日 10:00〜10:30 の予約 | バー内に開始時刻「10:00」と終了時刻「10:30」が表示される |
| 予約バー | 26分（境界の直後） | 🟢 正常系：当日 10:00〜10:26 の予約 | 開始時刻と終了時刻が表示される |
| 予約バー | 25分30秒（境界ちょうど） | 🟢 正常系：当日 10:00〜10:25:30 の予約 | 開始時刻と終了時刻が表示される |
| 予約バー | 25分（境界の直前） | 🟡 例外系：当日 10:00〜10:25 の予約 | バーは表示されるが、開始時刻・終了時刻は表示されない |
| 予約バー | 日をまたぐ | 🟢 正常系：前日 23:00〜当日 1:00 の予約 | 開始時刻が「11月3日 23:00」のように日付付きで、終了時刻が「1:00」と表示される |

---

### ルール④: タイムラインは一定間隔で現在時刻の位置へ自動でスクロールする

> 自動スクロールは「現在時刻の1時間前の目盛りを左端に合わせる」動きだが、**タイムラインの右端より先へはスクロールできない**。そのため現在時刻が遅い時間帯では右端で止まり、左端に来る目盛りは1時間前より手前になる。どの時刻から右端で止まるかは画面幅によって変わる。

| 対象 | 操作 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| タイムライン | 操作しない | 🟢 正常系：現在時刻が 10:30 で、何も操作せず10秒待つ | 9時の目盛りが左端に来る位置へスクロールする |
| タイムライン | 操作しない | 🟢 正常系：右端で止まる時間帯に、何も操作せず10秒待つ | 右端の「1」の目盛りが画面の右端に来た位置で止まり、それ以上は右へスクロールできない |
| タイムライン | 横スクロール | 🟢 正常系：手動でタイムラインを横にスクロールする | スクロールした位置が保たれ、最後に操作してから10秒後に現在時刻の位置へ戻る |
| 日付ラベル | 押下 | 🟢 正常系：日付ラベルを押す | その場で現在時刻の位置へスクロールする |

---

### ルール⑤: 予約バーを押すと、公開範囲に応じた内容の予約の詳細が表示される

> 件名・主催者名の出し分けは、**端末設定「予約情報の表示」が有効であること**を前提に、予約ごとの公開範囲（all／owner／none）で決まる。時間帯は公開範囲に関わらず常に表示される。
> 件名は workhub（Web）で作成されたものをそのまま表示する。タブレット側に文字数の上限は無いため、**長さの検証は文字数ではなく表示領域に対する行数**（1行に収まる／わずかに超える／大きく超える）で行う。

| 端末設定「予約情報の表示」 | 予約の公開範囲 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 有効 | all | 🟢 正常系：全員に公開された予約のバーを押す | 件名・時間帯（例「10:00~11:00」）・「主催者 ：◯◯」が表示される |
| 有効 | owner | 🟢 正常系：主催者のみ公開の予約のバーを押す | 件名は表示されず、時間帯と「主催者 ：◯◯」が表示される |
| 有効 | none | 🟢 正常系：非公開の予約のバーを押す | 件名も主催者名も表示されず、時間帯だけが表示される |
| 無効 | all／owner／none のいずれでも | 🟢 正常系：端末設定を無効にした状態で予約のバーを押す | 公開範囲に関わらず、件名も主催者名も表示されず、時間帯だけが表示される |
| 有効 | all | 🟢 正常系：件名が1行に収まる長さの予約のバーを押す | 件名が1行で表示される |
| 有効 | all | 🟢 正常系：件名が1行をわずかに超える長さの予約のバーを押す | 2行に折り返して表示され、欠けずに読める |
| 有効 | all | 🟡 例外系：件名が全角100文字の予約のバーを押す | 折り返して表示され、時間帯・主催者名も読める状態が保たれる |

---

### ルール⑥: 予約の詳細は閉じる操作でタイムラインに戻る

| 対象 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- |
| 予約の詳細 | 🟢 正常系：「閉じる」を選択する | 予約の詳細が閉じ、タイムラインに戻る |
| 予約の詳細 | 🟢 正常系：予約の詳細の外側を押す | 予約の詳細が閉じ、タイムラインに戻る |

---

### ルール⑦: 削除できる条件を満たす予約の詳細にだけ「予約削除」が表示される

> 削除できるかどうかの判定そのもの、および削除の実行は「予約をキャンセル・削除できる」の責務（台帳 #25）。本ルールは**ボタンが出るか出ないか**を対象とする。

| 対象 | 削除の可否 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 予約の詳細 | 可 | 🟢 正常系：削除できる条件を満たす予約のバーを押す | 「予約削除」と「閉じる」が表示される |
| 予約の詳細 | 不可 | 🔴 異常系：削除できる条件を満たさない予約のバーを押す | 「予約削除」は表示されず、「閉じる」だけが表示される |

---

### ルール⑧: 利用不可のときはホーム画面ごと利用不可の表示に差し替わる

> 利用不可（利用時間外、または予約設定上その時間は使えない）と判定されると、画面全体が利用不可の表示へ切り替わるため、タイムラインを含むホーム画面の内容は表示されない。**判定と利用不可画面の表示そのものは⑩「利用不可・利用時間外を表示できる」の責務**であり、本ルールは「ホーム画面が表示されている間はタイムラインが出る／利用不可では出ない」ことのみを対象とする。

| 対象 | 部屋の状態 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| タイムライン | 空室／入室待ち／利用中 | 🟢 正常系：いずれかの状態でホーム画面を表示する | ホーム画面の下部にタイムラインが表示される |
| タイムライン | 利用不可 | 🔴 異常系：利用不可の状態になる | ホーム画面ごと利用不可の表示に差し替わり、タイムラインは表示されない |

---

### ルール⑨: 表示中に予約が他の経路で変わるとタイムラインに反映される

> 予約データの同期そのものは対象外（③⑦の責務）。本ルールは**同期された結果がタイムラインの帯に現れること**を対象とする。

| 対象 | 他の経路での変更 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| タイムライン | 作成 | 🟢 正常系：タイムラインを表示中に、当日 14:00〜15:00 の予約がWeb等から作成される | タブレットを操作することなく、14時から15時の位置に帯が現れる |
| タイムライン | 削除 | 🟢 正常系：表示中の当日 14:00〜15:00 の予約がWeb等から削除される | タブレットを操作することなく、その帯が消える |
| タイムライン | 時刻の変更 | 🟢 正常系：表示中の当日 14:00〜15:00 の予約が 16:00〜17:00 に変更される | 帯が16時から17時の位置へ移る |
| タイムライン | 延長・短縮 | 🟢 正常系：表示中の当日 14:00〜15:00 の予約が 14:00〜16:00 に延長される | 帯の終わりが16時の位置まで伸びる |

---

### ルール⑩: スリープから復帰するとタイムラインが現在時刻に追いつく

| 対象 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- |
| タイムライン | 🟡 例外系：10:00 にタイムラインを表示したままスリープし、13:00 に復帰する | 現在時刻バーが13時の位置に表示され、自動スクロールも13時を基準とした位置になる |

---

### ❓ 疑問点・未確認事項（赤カード）
- [ ] **①** 予約の詳細の主催者名の解決方法（**開発と確認**）。受け入れ条件「クロス組織の顧客名など、表示可能な範囲でホスト名が解決される」に対し、参照元（iOS）のダイアログは予約データ内の参加者名をそのまま表示しており、⑨「予約の参加者情報を表示できる」のような取得・リトライを行っていない。Android版でどちらにするかの確定が必要。
