## ルールの洗い出しと正常系・異常系の分類

### 機能名: 設定値の読み込み（ブート画面 / BootScreen → 設定読み込み画面 / SettingLoaderScreen）
**機能概要:** アプリ起動時に端末権限の確認・保存済みログイン状態の確認・認証情報の更新を行い、すべて成功した場合のみサーバから設定値を自動取得する。取得結果に応じて起動準備画面・初期設定画面・設置手続きのいずれかへ自動的に振り分ける。ユーザーが操作する要素は、権限の付与を求める案内・復旧待ちが10回を超えた後のログアウト動線・スピナー・設置方法の選択画面のみ。

**起動から設定の読み込みまでの工程:** 以下の順に処理し、いずれかで止まった場合は後続の工程に進まない。

| 工程 | 内容 | 失敗時の扱い | 対応ルール |
| :--- | :--- | :--- | :--- |
| 権限確認 | カメラ・Bluetooth・位置情報の利用許可を確認する | 付与されるまで案内を表示し続ける | ルール① |
| ログイン状態の確認 | 端末内に保存されたログイン状態を確認する | ログインを要求する | ルール② |
| 認証情報の更新 | 保存済みの情報をもとに認証情報を更新する | 30秒間隔で上限なく再試行し、復旧不可の失敗のみログインを要求する | ルール③・④・⑤ |
| 設定の読み込み | 組織情報・端末設定を取得する | 下表のとおり | ルール⑥〜⑩ |

**取得する設定値と処理順序:** 設定の読み込みでは、以下の2種類のデータを①→②の順に取得する。①で失敗した場合、②には進まない。

| 順番 | 取得するデータ | 中身 | 失敗時の扱い |
| :--- | :--- | :--- | :--- |
| ① | 組織情報 | ログインした組織そのものの情報（どの組織としてこのタブレットを動作させるか） | 再試行せず、即座にログイン画面へ戻す（ルール⑩） |
| ② | 端末設定 | このタブレット1台分の設定（設置空間・解錠デバイス・予約設定など） | 30秒間隔で上限なく再試行し、復旧不可の失敗のみログイン画面へ戻す（ルール⑨） |

**再試行の回数・間隔・制限時間の出所:** 権限の再確認（5秒間隔）と更新1回あたりの制限時間（30秒）は実装値（iOS）。**再試行の間隔（30秒・上限なし）とログアウト動線の表示条件（10回超過）は 2026-10-14 のリファインメントでの決定値**であり、参照元（iOS）の実装値（認証情報の更新＝5秒間隔・最大3回／接続待ち中＝3秒間隔／端末設定の取得＝10秒間隔・最大3回）からは変更されている。

### ルール①: 起動に必要な端末権限（カメラ・Bluetooth・位置情報）が揃うまで、後続の処理へ進まない
> 権限の確認は「①権限ごとにOS標準の権限ダイアログが順に表示される → ②すべての応答が終わった時点で不足が残っていれば、アプリ側の権限確認の案内が表示される」の順で行われる。アプリ側の案内には端末の権限設定画面を開くためのボタンがあり、案内が表示されている間は5秒間隔で権限が再確認される。すべて許可された場合はアプリ側の案内は表示されず、そのままログイン状態の確認へ進む。
> 位置情報は、実装時に利用の必要がないと確認できた場合は対象から外す（必要という前提で記載している）。

| 対象 | 権限の状態 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| タブレット | カメラのみ未許可 | 🟡例外系：カメラの利用だけを許可していない状態で起動する | 不足している権限としてカメラの付与を求める案内が表示され続け、ログイン状態の確認へ進まない |
| タブレット | Bluetoothのみ未許可 | 🟡例外系：Bluetoothの利用だけを許可していない状態で起動する | 不足している権限としてBluetoothの付与を求める案内が表示され続け、ログイン状態の確認へ進まない |
| タブレット | 位置情報のみ未許可 | 🟡例外系：位置情報の利用だけを許可していない状態で起動する | 不足している権限として位置情報の付与を求める案内が表示され続け、ログイン状態の確認へ進まない |
| タブレット | カメラ・Bluetoothが未許可 | 🟡例外系：位置情報だけを許可した状態で起動する | 不足している2つの権限の付与を求める案内が表示され続け、ログイン状態の確認へ進まない |
| タブレット | カメラ・位置情報が未許可 | 🟡例外系：Bluetoothだけを許可した状態で起動する | 不足している2つの権限の付与を求める案内が表示され続け、ログイン状態の確認へ進まない |
| タブレット | Bluetooth・位置情報が未許可 | 🟡例外系：カメラだけを許可した状態で起動する | 不足している2つの権限の付与を求める案内が表示され続け、ログイン状態の確認へ進まない |
| タブレット | 3つすべてが未許可 | 🟡例外系：カメラもBluetoothも位置情報も許可していない状態で起動する | 不足している3つの権限の付与を求める案内が表示され続け、ログイン状態の確認へ進まない |
| タブレット | すべて許可 | 🟢正常系：OS側の権限ダイアログですべての権限を許可する | アプリ側の権限確認の案内は表示されず、ログイン状態の確認へ進む |
| タブレット | 未許可→許可 | 🟢正常系：案内の表示中に権限を付与する | 5秒間隔で権限が再確認され、揃った時点で案内が自動的に閉じられてログイン状態の確認へ進む |
| タブレット | 未許可（案内の表示中） | 🟢正常系：案内にある権限設定画面を開くためのボタンを選択する | 端末の権限設定画面が開く |
| タブレット | 権限設定画面で付与→復帰 | 🟢正常系：権限設定画面ですべての権限を付与し、バックグラウンド経由でアプリに戻る | 権限が再確認され、案内が閉じられてログイン状態の確認へ進む |
| タブレット | 権限設定画面で付与→復帰 | 🟢正常系：権限設定画面ですべての権限を付与し、画面左上の戻る操作でアプリに戻る | 戻り方が違っても結果は変わらず、権限が再確認され、案内が閉じられてログイン状態の確認へ進む |
| タブレット | 権限設定画面で未付与→復帰 | 🟡例外系：権限を付与せずにアプリに戻る | 案内が表示されたままとなり、ログイン状態の確認へ進まない |

### ルール②: 保存済みのログイン状態が「ログイン済み」でなければ、認証情報の更新を行わずログインを要求する
> 「状態を判定できない」は、端末内の保存領域（iOSのキーチェーンに相当）からログイン状態を読み出せなかった場合に生じる。利用者の操作に起因しない失敗のため例外系として扱い、正常系の振り分けとは別に検証する。

| 対象 | ログイン状態 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| タブレット | ログイン済み | 🟢正常系：前回のログイン情報が残っている状態で起動する | 認証情報の更新が開始される |
| タブレット | ログインしていない | 🟢正常系：ログイン情報が残っていない状態で起動する | 認証情報の更新は行われず、ログインが要求される |
| タブレット | 状態を判定できない | 🟡例外系：端末内の保存領域からログイン状態を読み出せない状態で起動する | 認証情報の更新は行われず、ログインが要求される（ログイン情報が残っていない場合と同じ扱いになる） |

---

### ルール③: 認証情報の更新は30秒間隔で自動再試行され、成功すると設定の読み込みへ進む
> 更新処理そのものには30秒の制限時間があり、時間内に終わらない場合も失敗として扱われ再試行へ回される。制限時間（30秒）と再試行の間隔（30秒）は同じ値だが別物である。
> 再試行に回数の上限はない。失敗が続いた場合の扱いはルール④で、再試行中の画面の扱いはルール⑤で定める。

| 対象 | 更新の結果 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| タブレット | 1回目で成功 | 🟢正常系：起動直後の認証情報の更新が成功する | 初期化中であることを示す表示（「初期化中 ...」「最大30秒ほどかかる場合があります」）が閉じられ、設定の読み込みが開始される |
| タブレット | 再試行で成功 | 🟢正常系：1回目に失敗し、30秒後の再試行で成功する | 設定の読み込みが開始される |
| タブレット | 再試行を重ねて成功 | 🟢正常系：30秒間隔の再試行を複数回重ねた後に成功する | 再試行の回数によらず、成功した時点で設定の読み込みが開始される |
| タブレット | 時間超過 | 🟡例外系：更新処理が30秒以内に終了しない | 失敗として扱われ、30秒待機の後に再試行される（設定の読み込みは開始されない） |

---

### ルール④: 認証情報の更新が失敗し続けた場合は、復旧不可のときだけログインが要求され、それ以外は復旧を待つ
> 分岐の軸は「復旧不可か否か」の一点のみ。**復旧不可に該当しない失敗はすべて復旧を待つ**（復旧を待つ側に回数の上限はなく、復旧するまで30秒間隔の再試行が続く）。
> **復旧不可**に該当するのは、①認証情報の再取得に必要な情報が端末内に無い場合、②認証エラー（401）の2つ。前者は案内なしで、後者は案内を表示したうえでログインが要求される。
> **復旧を待つ**側には、サーバーエラー（500・503）、通信エラー（オフライン・タイムアウト）のほか、リクエスト不正（400）・認可エラー（403）・対象が見つからない（404）・レスポンスを解釈できない場合・端末の保存領域を参照できない場合も含まれる。復旧を待つ間はエラーダイアログを表示しない（画面の扱いはルール⑤）。
> 端末内に設定の控えが残っている端末も残っていない端末も存在するが、Android版は予約認証モードのみに対応するため、控えの有無によって到達先は変わらない（控えを用いた起動は行われない）。したがって控えの有無は分岐の軸としない。

| 対象 | 復旧可否 | 失敗要因 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- | :--- |
| タブレット | 復旧不可 | 認証情報の再取得に必要な情報なし | 🟡例外系：再取得に必要な情報が端末内に保存されていない状態で失敗する | 案内は表示されず、保存済みのログイン状態が破棄されてログインが要求される |
| タブレット | 復旧不可 | 認証エラー（401） | 🟡例外系：認証エラーで失敗する | 「token失効により自動ログインに失敗しました」が表示された後、保存済みのログイン状態が破棄されてログインが要求される |
| タブレット | 復旧を待つ | サーバーエラー（500・503） | 🟡例外系：サーバーエラーで失敗し続ける | エラーダイアログは表示されず、ログインも要求されず、復旧を待つ状態になって30秒間隔の再試行が続けられる |
| タブレット | 復旧を待つ | 通信エラー（オフライン・タイムアウト） | 🟡例外系：通信エラーで失敗し続ける | エラーダイアログは表示されず、ログインも要求されず、復旧を待つ状態になって30秒間隔の再試行が続けられる |
| タブレット | 復旧を待つ | 上記以外のすべての失敗（400・403・404・レスポンスを解釈できない・端末の保存領域を参照できない） | 🟡例外系：復旧不可に該当しない失敗で失敗し続ける | 失敗の種類によらず、エラーダイアログは表示されず、ログインも要求されず、復旧を待つ状態になって30秒間隔の再試行が続けられる |
| タブレット | 復旧不可 | 認証エラー（端末内に設定の控えあり） | 🟡例外系：端末内に設定の控えが残っている状態で、認証エラーで失敗する | 控えを用いた起動は行われず、控えが無い場合と同じくログインが要求される |
| タブレット | 復旧を待つ | 通信エラー（端末内に設定の控えあり） | 🟡例外系：端末内に設定の控えが残っている状態で、通信エラーで失敗し続ける | 控えを用いた起動は行われず、控えが無い場合と同じく復旧を待つ状態になる |

---

### ルール⑤: 復旧を待っている間は待機理由と再試行の秒数が示され、再試行が10回を超えるとログアウト動線が表示される
> ルール④で「復旧を待つ」と判定された場合の画面の扱い。待っているだけの画面にせず、**なぜ復旧を待っているのか**と**再試行の秒数**を示す。
> ログアウト動線は最初から出さず、**再試行が10回を超えた時点**（30秒間隔のため約5分後）で表示する。それまでは利用者の操作を求めない。

| 対象 | 状態 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| タブレット | 復旧待ち（1回目） | 🟢正常系：復旧を待っている状態を表示する | 復旧を待っていることとその理由、および再試行の秒数が表示され、自動では先へ進まない |
| タブレット | 復旧待ち（10回目まで） | 🟢正常系：再試行が10回目まで続く | 待機理由と再試行の秒数が表示され続け、ログアウト動線は表示されない |
| タブレット | 復旧待ち（10回超過） | 🟢正常系：再試行が10回を超える | ログアウト動線が表示される（待機理由と再試行の秒数の表示は継続する） |
| タブレット | 復旧待ち→復旧 | 🟢正常系：30秒後に認証情報の更新がやり直され、成功する | 設定の読み込みが開始される |
| タブレット | 復旧待ち→利用者操作 | 🟢正常系：10回超過後に利用者がログアウト動線を選択する | ログインが要求される |

### ルール⑥: 初期設定が完了している端末は、起動後に自動で設定が読み込まれ起動準備画面へ進める

| 対象 | 端末設定 | 初期設定状態 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- | :--- |
| タブレット | あり | 完了 | 🟢正常系：設定が存在し初期設定完了済みの端末で起動する | 「設定を読み込んでいます」スピナー表示後、起動準備画面へ自動遷移する |
| タブレット | あり | 完了 | 🟢正常系：読み込み完了まで画面に操作要素が表示されない | スピナー表示のみで、ユーザー操作を求められない |
| タブレット | あり | 完了 | 🟡例外系：読み込み中にアプリを終了し再起動する | 再度「設定を読み込んでいます」から読み込みがやり直される |

---

### ルール⑦: 初期設定が未完了の端末は、起動準備へ進まず初期設定画面へ誘導される

| 対象 | 端末設定 | 初期設定状態 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- | :--- |
| タブレット | あり | 未完了 | 🟢正常系：初期設定が未完了の端末で起動する | 初期設定画面へ遷移する |
| タブレット | あり | 完了 | 🟢正常系：初期設定が完了している端末で起動する | 初期設定画面へは遷移せず起動準備画面へ進む |

### ルール⑧: 端末設定が登録されていない端末は、設置方法（再設置／新規設置）を選んで設置手続きに進める
> 設置方法の選択は**ダイアログではなく画面**として提示する（現状のAndroid実装に合わせる）。画面にはログアウト動線を設ける。
> 「新規設置」を押した時点で**ボタンを押せない状態にし、処理中であることを示す案内とインジケータを表示する**（押せないだけだと利用者が状況を判断できないため、案内を必ず伴わせる）。
> 「新規設置」選択後の端末設定の作成では、組織情報の取得と端末設定の新規作成のいずれかで失敗が起こりうる。**失敗してもログインは要求せず**、設置方法の選択画面に留まり再実行できる。エラーの文言は**失敗の種類が何かがわかる表記**で出し分ける（具体的な文言は赤カードで確定する）。
> 新規設置が成功した場合はテンプレートの選択へ進む。

| 対象 | 端末設定 | 選択操作 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- | :--- |
| タブレット | なし | -（表示時） | 🟢正常系：端末設定が未登録の状態で起動する | 「設置方法を選択してください」「再設置を行うと元のタブレットではデータを利用できなくなります。」が画面として表示され、ログアウト動線も表示される |
| タブレット | なし | 再設置 | 🟢正常系：「再設置」を選択する | 再インストール画面へ遷移する |
| タブレット | なし | 新規設置 | 🟢正常系：「新規設置」を押した直後の状態を確認する | 選択操作のボタンが押せない状態になり、処理中であることを示す案内（「初期設定を行っています」）とインジケータが表示される |
| タブレット | なし | 新規設置 | 🟢正常系：「新規設置」を選択して端末設定の作成が成功する | テンプレートの選択へ進む |
| タブレット | なし | 新規設置 | 🟡例外系：組織情報の取得に失敗する | 組織情報を取得できなかったことがわかるエラーダイアログが表示され、ログインは要求されず設置方法の選択画面に留まる |
| タブレット | なし | 新規設置 | 🟡例外系：端末設定の新規作成が通信エラー（オフライン・タイムアウト）で失敗する | 通信に問題があったことがわかるエラーダイアログが表示され、ログインは要求されず設置方法の選択画面に留まる |
| タブレット | なし | 新規設置 | 🟡例外系：端末設定の新規作成がサーバーエラーで失敗する | サーバー側の問題であることがわかるエラーダイアログが表示され、ログインは要求されず設置方法の選択画面に留まる |
| タブレット | なし | 新規設置 | 🟡例外系：端末設定の新規作成が認証・認可エラーで失敗する | 認証・認可に問題があったことがわかるエラーダイアログが表示され、ログインは要求されず設置方法の選択画面に留まる |

### ルール⑨: 端末設定の取得・起動時更新に失敗した場合は、復旧不可のときだけログインが要求され、それ以外は復旧を待つ
> 対象は処理順序②の「端末設定」の取得・更新。①の組織情報の取得失敗はルール⑩で扱う。
> 分岐の軸はルール④と同じく「復旧不可か否か」。**復旧不可に該当しない失敗はすべて30秒間隔で復旧を待ち続ける**（回数の上限はなく、エラーメッセージも表示せず、ログインも要求しない）。復旧を待っている間の画面の扱いはルール⑤と同じ。
> **復旧不可**に該当するのは、①端末設定の取得での認証・認可の失敗、②取得できた端末設定のIDが不正、③起動時更新で端末設定のIDが解決できない・鍵の保管庫が見つからない、④起動時更新での認証・認可エラー（401・403）の4つ。いずれも待っても解消しないため、エラーダイアログを表示してログイン画面へ戻す。
> **端末設定の取得はデータベースから直接読み出しており、HTTPのステータスコードを持たない。**復旧可否はデータベース側のエラー種別（認証・認可の失敗か、サーバー都合の一時的な失敗か）で判定する必要がある。
> **再試行は設定の読み込み全体のやり直しとなる**ため、再試行のたびに①の組織情報の取得からやり直される。再試行の途中で組織情報の取得が失敗した場合は、ルール⑩の扱い（即ログイン画面へ）になる。
> **エラー文言の(1)と(2)は「取得で失敗したか・更新で失敗したか」では分かれない。**参照元（iOS）では実装上の例外の種類で分岐しており、結果として下表の対応になる。

| 対象 | 復旧可否 | 失敗要因 | 失敗継続 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- | :--- | :--- |
| タブレット | 復旧を待つ | 端末設定の取得失敗（サーバー都合の一時的な失敗・タイムアウト） | 再試行中に復旧 | 🟡例外系：取得に失敗した後、再試行中に復旧する | スピナー表示が継続し、復旧後に起動準備画面へ遷移する |
| タブレット | 復旧を待つ | 端末設定の取得失敗（サーバー都合の一時的な失敗・タイムアウト） | 継続 | 🟡例外系：サーバー都合の失敗が継続する | エラーメッセージは表示されず、ログインも要求されず、30秒間隔の再試行が続けられる |
| タブレット | 復旧不可 | 端末設定の取得での認証・認可の失敗 | 継続 | 🟡例外系：端末設定の取得が認証・認可の失敗で拒否される | 「端末情報の取得に失敗しました(2)」のエラーダイアログが表示され、ログイン画面へ戻る |
| タブレット | 復旧不可 | 端末設定は取得できるがIDが不正 | 継続 | 🟡例外系：取得した端末設定のIDが不正な状態が継続する | 「端末情報の取得に失敗しました(1)」が表示され、ログイン画面へ戻る |
| タブレット | 復旧不可 | 起動時更新の失敗（端末設定がIDを持たない・鍵の保管庫が見つからない） | 継続 | 🟡例外系：起動時更新で端末設定のIDが解決できない、または鍵の保管庫を取得できない状態が継続する | 「端末情報の取得に失敗しました(1)」が表示され、ログイン画面へ戻る |
| タブレット | 復旧不可 | 起動時更新の認証・認可エラー（401・403） | 継続 | 🟡例外系：起動時更新が認証・認可エラーで失敗する | 「端末情報の取得に失敗しました(2)」が表示され、ログイン画面へ戻る |
| タブレット | 復旧を待つ | 起動時更新のその他の失敗（500・503・通信エラーなど） | 継続 | 🟡例外系：起動時更新がその他の要因で失敗し続ける | エラーメッセージは表示されず、ログインも要求されず、30秒間隔の再試行が続けられる |

### ルール⑩: 組織情報の取得に失敗した場合は、再試行されずに即座にログイン画面へ戻される
> 対象は処理順序①の「組織情報」の取得。同じ一時的な通信失敗でも、②の端末設定の取得（ルール⑨）は自動再試行で復旧できるのに対し、①の組織情報の取得は再試行されず、必ずログインからやり直しになる。

| 対象 | 失敗要因 | 再試行 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- | :--- |
| タブレット | 組織情報の取得失敗 | なし | 🟡例外系：起動直後に組織情報の取得が失敗する | 再試行されず「組織情報の取得に失敗しました(1)」のエラーダイアログが表示され、ログイン画面へ戻る |
| タブレット | 組織情報の取得失敗（1回目のみ） | なし | 🟡例外系：組織情報の取得が1回目のみ失敗し、2回目以降は成功する状態で起動する | 1回目の失敗時点でエラーダイアログが表示され、ログイン画面へ戻る（再試行されないため、2回目以降が成功する状態でも起動できない） |
| タブレット | 再試行中の組織情報の取得失敗 | なし | 🟡例外系：端末設定の取得が失敗し続ける再試行中に、組織情報の取得も失敗する | 端末設定の再試行の上限を待たず、「組織情報の取得に失敗しました(1)」のエラーダイアログが表示され、ログイン画面へ戻る（再試行は組織情報の取得からやり直されるため） |

### ✅ 確定した仕様（確認済み）

- [x] **「再設置」選択後の戻る操作**: 再設置の手続きから戻る操作は可能とし、設置方法の選択に戻る。→ ルール⑧に反映済み。
- [x] **起動時更新処理のうち顔情報の再取得**: アプリバージョン差分時の顔情報の再取得は別機能として扱い、本機能のスコープ外とする。
- [x] **控えを用いた起動の成立条件**（iOSソースで確認済み）: 仕様書の「その他エラー」という記載より広く、認証情報の再取得に必要な情報が無い場合を除くすべての失敗で、控えがあれば控えを用いた起動が優先される。控えは「控えを使う設定が有効な端末で、端末設定を読み込んだとき」に作られる。**ただしこれはiOS版の挙動であり、Android版には適用しない**（下記参照）。
- [x] **Android版では控えを用いた起動が行われない**（2026-10-08 のリファインメントで確定）: Android版は予約認証モードのみに対応するプロダクトであるため、端末内の設定の控えの有無によって到達先は変わらない。控えが残っている端末でも、認証情報の更新の失敗要因のみで結果が決まる。→ ルール④に反映済み。これによりPBIの受け入れ条件「予約認証モードのキャッシュではオフライン起動用の画面へ遷移しない」との矛盾は解消した。

- [ ] **起動時更新処理を本PBIの受け入れ範囲に含めるか**: 最終起動日時の記録、再起動中フラグの解除、ログインペルソナ／シリアル番号の更新、設定値のマイグレーション・正規化、存在しない解錠デバイスの紐付け解除、および「変更が生じた場合のみ更新する」判定は、いずれも画面上に現れないためブラックボックス検証の対象外になる可能性が高い。本資料のルール⑨は起動時更新の「失敗」しか扱っていない。別機能として切り出すか、本PBIでルール化するかを確定したい。
- [ ] **起動時の準備処理のうち、利用者から観測できる差があるもの**: 起動時にはアプリ固有情報の初期化と端末内の顔情報の有無の確認が行われるが、顔情報の有無によって画面表示・遷移先に差が生じるかが未定義。また、通信状態の確認が認証情報の更新とは別の処理として存在するかも未定義。観測可能な差が無ければ本資料の対象外とする。
- [ ] **仕様が未定義のまま残っている観点（一括）**: 以下はいずれも仕様書・ソースから確定できないため、推測での仕様化を行っていない。(a) 権限は付与済みだがBluetoothがOFFの場合に案内が表示されるか／文言が変わるか、(b) カメラのみ許可など片方だけ解消した場合の案内の変化、(d) 認証情報の更新の再試行中に権限が取り消された場合の優先順位、(e) 再試行の途中でアプリを終了・再起動した場合に再試行回数がリセットされるか、(f) 再試行のたびに失敗要因が変わる場合（1回目は通信エラー・2回目は認証エラー等）にどの分岐へ進むか、(g) 復旧待ち中の再試行の失敗要因が復旧不可に変わった場合の扱い、(h) 復旧待ち中にログアウト動線を選んだ後、進行中の再試行が停止するか、(i) 強制ログアウトで消える情報の範囲（控え・顔情報・端末の識別情報）と再ログイン後に同じ端末設定へ戻れるか、(j) 端末設定の取得1回あたりに制限時間があるか、(k) 端末設定は存在するがログイン中の組織と一致しない場合、(l) 旧形式の設定値を持つ端末設定で起動した場合の正規化、(m) 読み込み完了後にサーバ側の設定が変更された場合、再起動まで反映されないことを仕様とするか。
- [ ] **Androidの戻るキーで設置方法の選択が閉じるか**: 選択肢以外の領域をタップしても閉じないことは実装で確認済み（`enableOutsideClick: false`）だが、Android特有の戻るキー操作での挙動は参照元（iOS）から確認できない。Android実装での期待値を確定したい。
