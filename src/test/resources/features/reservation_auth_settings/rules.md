## ルールの洗い出しと正常系・異常系の分類

### 機能名: 予約認証設定の変更
**機能概要:** 管理者が管理者メニューからタブレット設定画面を開き、予約認証モードに関連する全設定項目（基本設定・パスワード・認証・画面表示/機能制御・利用時間・デバイス/解施錠・SE/通知・顔認証）を変更して保存する。初期設定とは異なり、既存設定の編集フローであり、全項目に初期値が設定済みの状態から変更操作を行う。キャンセル操作や既存設定コピーが利用可能。

**スコープ:** 予約認証モードに関連する設定項目のみを対象とする。認証モード（予約認証／常時認証）の切り替え、および常時認証モード専用の設定項目は対象外とする。

---

### ルール①: 管理者は予約認証モードの設定を変更して保存できる
**推奨テスト階層:** Presentation Unitテスト (JVM / Turbine)
**割り振り理由:** 設定変更→保存要求→遷移要求までのUI状態変化はViewModelのストリーム検証で完結するため。（※保存後の他画面への反映は Application Unitテストで別途検証する）

| 対象 | 操作 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 管理者 | 設定変更して保存 | 🟢正常系：認証方法・予約作成可否・自動キャンセル等を変更して保存 | 変更内容が端末設定として保存される |
| 管理者 | 変更せずに保存 | 🟢正常系：何も変更せずに保存を実行 | 変更前と同じ内容で保存が実行され、設定コピー確認に進む |
| 管理者 | 保存を連打 | 🟢正常系：保存を連続して要求する | 保存中は進行表示が画面全体に表示されて操作を受け付けず、保存処理は1回のみ実行される |
| 管理者 | 保存失敗 | 🟡例外系：設定保存APIが失敗 | エラー「タブレット情報の保存に失敗しました」が表示され、設定画面に留まる |

---

### ルール②: 保存後の変更内容は関連する各画面に反映される
**推奨テスト階層:** Application Unitテスト (JVM)
**割り振り理由:** 保存→端末設定の更新→複数画面の表示条件の変化という、画面をまたぐ一連のユースケースフローであり、単一ViewModelのストリーム検証では閉じないため。

| 対象 | 変更した設定 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 管理者 | 予約作成（今すぐ入室） | 🟢正常系：予約作成をOFFにして保存 | ホーム画面に今すぐ入室の操作が表示されなくなる |
| 管理者 | 予約情報の表示 | 🟢正常系：予約情報の表示を「非表示」にして保存 | ホーム画面に予約の詳細情報が表示されなくなる |
| 管理者 | 認証方法 | 🟢正常系：認証方法を「QRのみ」から「QR＋顔」に変更して保存 | カメラ認証画面で顔認証が利用できるようになる |
| 管理者 | タブレット名 | 🟢正常系：タブレット名を変更して保存 | ホーム画面に表示される名称が変更後の名称になる |
| 管理者 | 保存後の戻り先 | 🟢正常系：管理者メニューから設定画面を開いて保存 | 管理者メニューに戻る |
| 管理者 | 保存後の戻り先 | 🟢正常系：管理者メニュー以外から設定画面に到達して保存 | トップ画面（ホーム）に戻る |

### ルール③: 設定画面を開いたとき、保存済みの現在値と予約認証モードに応じた項目が表示される
**推奨テスト階層:** Presentation Unitテスト (JVM / Turbine)
**割り振り理由:** 画面初期化時のUiState構築（保存済み値のロードと項目の出し分け）はViewModelのストリーム検証で完結するため。

| 対象 | 観点 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 管理者 | 現在値のロード | 🟢正常系：設定済みの端末で設定画面を開く | タブレット名・スペース・認証方法・各トグル・各数値など、保存済みの値がすべての項目に反映されている |
| 管理者 | 現在値のロード | 🟢正常系：親設定が有効な状態で設定画面を開く | 子項目が展開された状態で、保存済みの値とともに表示される |
| 管理者 | モードによる出し分け | 🟢正常系：予約認証モードの端末で設定画面を開く | 常時認証モード専用の項目（自動チェックイン等）が表示されない |
| 管理者 | オプションによる出し分け | 🟢正常系：顔認証オプションが有効な組織で設定画面を開く | 顔認証セクションが表示される |
| 管理者 | オプションによる出し分け | 🟢正常系：顔認証オプションが無効な組織で設定画面を開く | 顔認証セクションが表示されず、認証方法の「顔」は選択できない状態で「顔認証の利用申請が必要」である旨が表示される |
| 管理者 | キャンセルの可否 | 🟢正常系：タブレット名と設置空間が設定済みの状態で設定画面を開く | キャンセルの操作が提供される |
| 管理者 | キャンセルの可否 | 🟢正常系：タブレット名または設置空間が未設定の状態で設定画面に誘導される | キャンセルの操作は提供されず、保存しないと離脱できない |

### ルール④: 予約認証モードのスペース選択には予約設定のあるスペースのみ表示される
**推奨テスト階層:** Presentation Unitテスト (JVM / Turbine)
**割り振り理由:** スペース一覧のフィルタリング表示はViewModelの状態変化であり、ストリーム検証で完結するため。

| 対象 | スペースの状態 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 管理者 | 予約設定あり（通常予約） | 🟢正常系：通常予約の設定があるスペース | スペース選択項目に表示され、選択できる |
| 管理者 | 予約設定あり（サードプレイス） | 🟢正常系：サードプレイスの設定があるスペース | スペース選択項目に表示され、選択できる |
| 管理者 | 予約設定なし | 🟢正常系：予約設定のないスペース | スペース選択項目に表示されず、選択できない |
| 管理者 | 予約設定ありが0件 | 🔴異常系：予約設定のあるスペースが1件も存在しない | スペース選択項目に選択肢が表示されず、スペースを選択できない |
| 管理者 | 一覧の取得失敗 | 🟡例外系：スペース一覧の取得に失敗する | スペース選択項目に選択肢が表示されない |

> **注記:** 現在設定済みのスペースが後から予約設定なしになった場合の表示は仕様未確定のため赤カードとする。

### ルール⑤: 顔認証を含まない認証方法では顔認証必須の機能を有効化できない
**推奨テスト階層:** Presentation Unitテスト (JVM / Turbine)
**割り振り理由:** 認証方法と機能制御の依存関係チェック、およびインラインアラート・保存時ダイアログの表示はViewModelのUiState変化であり、ストリーム検証で完結するため。

**制御の3層構造:**
```
[1] 顔認証オプション未契約  … 「予約作成(今すぐ入室)」「予約削除」のチェック自体が非活性
                              ＋「顔認証の利用申請が必要です」の案内を表示
[2] 契約済み・顔認証OFF     … 有効化した瞬間にセクション内へインラインのエラー表示
                              「別の設定を変更する必要があります」＋その場に「認証方法」設定を展開
[3] 保存時                  … バリデーションダイアログに
                              「『タブレットからの機能制御』>『予約作成（今すぐ入室）』が不適切です」
```

| 対象 | 顔認証オプション | 認証方法 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- | :--- |
| 管理者 | 有効 | 顔認証を含む | 🟢正常系：顔認証を含む認証方法で予約作成を有効化 | 予約作成機能が有効化され、エラーは表示されない |
| 管理者 | 無効 | - | 🔴異常系：顔認証オプション未契約の組織で予約作成を有効化しようとする | 「予約作成（今すぐ入室）」「予約削除」のチェックが非活性であり、「顔認証の利用申請が必要」である旨が表示される |
| 管理者 | 有効 | QRのみ | 🔴異常系：QRのみの状態で予約作成を有効化する | 有効化した時点でセクション内に「別の設定を変更する必要があります」が表示され、その場で認証方法を変更できる導線が提示される |
| 管理者 | 有効 | QRのみ | 🔴異常系：QRのみの状態で予約削除を有効化する | 同上 |
| 管理者 | 有効 | QRのみ | 🔴異常系：エラーを解消しないまま保存する | エラーダイアログに「『タブレットからの機能制御』>『予約作成（今すぐ入室）』が不適切です」が表示され、保存されない |
| 管理者 | 有効 | QRのみ→顔を追加 | 🟢正常系：提示された導線からその場で顔認証を有効にする | エラー表示が解消され、要件を満たした旨が表示される。そのまま保存できる |

### ルール⑥: 顔認証を認証方法から外すと、顔認証を必須とする機能も同時に無効になる
**推奨テスト階層:** Presentation Unitテスト (JVM / Turbine)
**割り振り理由:** 依存元の変更に伴う確認ダイアログの表示と依存先の一括更新はViewModelの状態変化であり、ストリーム検証で完結するため。

**影響を受ける項目:** 「タブレットからの機能制御」>「予約作成(今すぐ入室)」／「予約削除」、「顔認証を必要とする機能」>「入室」／「退室」／「延長」

| 対象 | 依存先の状態 | 操作 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- | :--- |
| 管理者 | 依存先が有効 | 顔認証を外す | 🟢正常系：依存先の機能が有効な状態で認証方法から顔認証を外す | 確認ダイアログ「「顔認証」を無効にしますか？」が表示され、同時に無効になる項目が一覧で提示される |
| 管理者 | 依存先が有効 | 確認して無効化 | 🟢正常系：確認ダイアログで無効化を確定する | 顔認証が無効になり、一覧に提示された項目もすべて無効になる。設定を変更した旨が通知される |
| 管理者 | 依存先が有効 | キャンセル | 🟢正常系：確認ダイアログでキャンセルする | 顔認証は有効のまま戻り、依存先の項目も変更されない |
| 管理者 | 依存先がすべて無効 | 顔認証を外す | 🟢正常系：依存先の機能がすべて無効な状態で顔認証を外す | 確認ダイアログは表示されず、そのまま顔認証が無効になる |

### ルール⑦: バリデーションエラーがある場合はセクション別にエラーが提示され保存できない
**推奨テスト階層:** Presentation Unitテスト (JVM / Turbine)
**割り振り理由:** バリデーション状態、エラーダイアログの内容、サイドバーのエラー件数バッジはいずれもViewModelのUiState変化であり、実機描画なしで検証可能なため。

**表示される項目は「表示されているもの」のみが検証対象となる。** 非表示の項目に不正値が残っている場合は、デフォルト値に復元されたうえで保存される。

| 対象 | エラー状態 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 管理者 | エラー1件 | 🔴異常系：1項目が不正な状態で保存 | エラーダイアログにタイトル「不正な入力値が存在します。入力値を修正してから再度保存してください。」と、セクション名つきでエラー内容が表示される。保存は実行されない |
| 管理者 | エラー3件 | 🔴異常系：3項目が不正な状態で保存 | 3件すべてがセクションごとに列挙される（「他N件」は表示されない） |
| 管理者 | エラー4件 | 🔴異常系：4項目が不正な状態で保存 | 3件が列挙され、末尾に「他1件」が表示される |
| 管理者 | 複数セクション | 🔴異常系：複数セクションに不正な項目がある | 各セクションのサイドバー項目にエラー件数バッジが表示される |
| 管理者 | エラー修正後 | 🟢正常系：エラーを修正して再度保存する | エラーが解消され、保存が実行される |
| 管理者 | 非表示項目のエラー | 🟢正常系：不正値を入力した項目を、親設定をOFFにして非表示にしてから保存 | 非表示の項目は検証対象外となり、デフォルト値に復元されて保存される |

### ルール⑨: 設定保存成功後、設定コピーの登録と完了遷移が行われる
**推奨テスト階層:** Presentation Unitテスト (JVM / Turbine)
**割り振り理由:** コピー登録選択→完了遷移のUI状態遷移であり、ViewModelのストリーム検証で完結するため。

| 対象 | コピー選択 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 管理者 | コピーする | 🟢正常系：識別名称を入力してコピー登録 | 設定コピーが登録され、管理者メニューに戻る |
| 管理者 | コピーしない | 🟢正常系：コピーしないを選択 | コピーせずに管理者メニューに戻る |
| 管理者 | コピーする | 🔴異常系：識別名称を入力せずに登録を試みる | 登録ボタンが無効化されており登録できない |
| 管理者 | コピーする | 🟡例外系：設定コピー登録APIが失敗 | エラー「タブレット情報の保存に失敗しました」が表示される。設定の保存自体は完了している |

> **注記:** 識別名称の重複可否・最大文字数、コピー登録失敗後の再試行導線は仕様未確定のため赤カードとする。

### ルール⑩: 保存時、条件を満たす場合に常時接続推奨ダイアログが表示される
**推奨テスト階層:** Presentation Unitテスト (JVM / Turbine)

**表示条件（すべて満たす場合のみ表示）:** 常時接続が無効 ＋ 解錠対象デバイスが1台のみ ＋ そのデバイスがGate型

| 対象 | 条件 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 管理者 | 条件を満たす | 🟢正常系：「有効化する」を選択 | 常時接続が有効になり保存が続行される（常時接続対象デバイスの選択内容は変わらない） |
| 管理者 | 条件を満たす | 🟢正常系：「そのまま保存する」を選択 | 常時接続は無効のまま保存が続行される |
| 管理者 | 常時接続が既に有効 | 🟢正常系：常時接続を有効にした状態で保存 | ダイアログは表示されず、そのまま保存される |
| 管理者 | 解錠デバイスが2台 | 🟢正常系：解錠対象デバイスを2台設定して保存 | ダイアログは表示されず、そのまま保存される |
| 管理者 | Gate型以外 | 🟢正常系：Gate型以外のデバイスを1台設定して保存 | ダイアログは表示されず、そのまま保存される |

### ルール⑪: 設定編集中に既存設定をコピーして上書きできる
**推奨テスト階層:** Presentation Unitテスト (JVM / Turbine)
**割り振り理由:** コピーボタンタップ後の確認ダイアログと遷移はViewModelの状態変化であり、ストリーム検証で完結するため。

| 対象 | 操作 | コピー元 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
