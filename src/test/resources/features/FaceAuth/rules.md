## ルールの洗い出しと正常系・異常系の分類

### 機能名: 顔認証で利用者を特定できる

**機能概要:** カメラ認証画面（予約認証モード用）で、カメラに映った顔から利用者本人を特定し、特定結果を持って操作ごとの画面へ進むまでを扱う。解錠と入退室の更新はこの画面では行わず、特定結果を受け取った先の画面が行う。

**処理の順序:** ①ホーム画面の操作ボタンからカメラ認証画面に入るとカメラが起動し、**認証待ち**になる → ②顔が映ると顔の特徴量が取り出され、端末内の顔情報と照合される → ③類似度が端末設定の**認証成功類似度**を超えたときだけ人物の特定に進み、見出しが**照会中**に変わる → ④人物情報を取得し、認証手段を顔認証とした特定結果を持って、操作ごとの画面へ進む。②③で条件を満たさない間は認証待ちのまま。

**合否の判定:** 画面に出ている要素と、そこに書かれている文言で判定する。

**画面の要素の呼称:**

- **見出し** … 画面上部の案内（「QRコードまたは顔を画面に映してください」「照会中です...」など）
- **映り方の案内** … カメラ映像に重ねて出る、顔の位置・角度・環境についての案内（「もう少し下に移動してください」など）

**注記:** 映り方の案内が出るまでの待ち時間（同じ状態が **1秒** 続いたら出る。なりすまし防止に関わる案内だけは即時）は参照元（iOS）の実装値。

| :--- | :--- | :--- | :--- |
| 利用者 | QRと顔 | 🟢正常系：ホーム画面の操作ボタンからカメラ認証画面に入る | カメラ映像が表示され、見出しに「QRコードまたは顔を画面に映してください」が出る |

### ルール②: 端末に顔情報が同期済みの人物の顔が映ると、人物が特定されて操作ごとの画面へ進む

> 一致と判定されるのは、類似度が端末設定の **認証成功類似度を超えた** ときだけ（同値は一致としない）。設定できる範囲は 0.7〜1。
> 類似度の実測値は、管理メニューの「顔認識機能のデバッグ」画面で % として確認できる。

| 対象 | 端末内の顔情報 | 認証成功類似度 | 操作 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 従業員 | 同期済み | 既定値 | 入室 | 🟢正常系：ホーム画面の「入室」から顔認証に進み、登録済みの本人がカメラに顔を映す | 見出しが「照会中です...」に変わり、ホーム画面で入室の処理が進む |
| 従業員 | 同期済み | 既定値 | 退室 | 🟢正常系：「退室」から顔認証に進み、登録済みの本人が顔を映す | 見出しが「照会中です...」に変わり、ホーム画面で退室の処理が進む |
| 従業員 | 同期済み | 既定値 | 今すぐ予約 | 🟢正常系：「今すぐ入室」から顔認証に進み、登録済みの本人が顔を映す | 見出しが「照会中です...」に変わり、予約作成の画面が開く |
| 従業員 | 同期済み | 既定値 | 延長 | 🟢正常系：「延長」から顔認証に進み、登録済みの本人が顔を映す | 見出しが「照会中です...」に変わり、延長時間を設定する画面が開く |
| 従業員 | 同期済み | 既定値 | 予約削除 | 🟢正常系：予約削除の導線から顔認証に進み、登録済みの本人が顔を映す | 見出しが「照会中です...」に変わり、ホーム画面で削除の処理が進む |
| 従業員 | 同期済み | 既定値 | 再解錠 | 🟢正常系：再解錠の導線から顔認証に進み、登録済みの本人が顔を映す | 見出しが「照会中です...」に変わり、ホーム画面で解錠の処理が進む |
| 従業員 | 同期済み | 下限（0.7） | 入室 | 🟢正常系：登録済みの本人がカメラに顔を映す | 見出しが「照会中です...」に変わり、ホーム画面で入室の処理が進む |
| 従業員 | 同期済み | 上限（1） | 入室 | 🔴異常系：登録済みの本人がカメラに顔を映す | 照会中にならず認証待ちのまま、映り方の案内に「顔情報が未登録です」が出る（類似度が1を超えることはないため一致しない） |
| 従業員 | 同期済み（想定最大件数） | 既定値 | 入室 | 🟢正常系：顔情報が想定最大件数まで同期された端末で、登録済みの本人がカメラに顔を映す | 見出しが「照会中です...」に変わり、ホーム画面で入室の処理が進む（件数は `criteria.md` の PE-07 を参照） |
| 利用者 | 顔情報が端末に無い | 既定値 | 入室 | 🔴異常系：顔を登録していない人物がカメラに顔を映す | 照会中にならず認証待ちのまま、映り方の案内に「顔情報が未登録です」が出る |

### ルール③: 顔の映り方が条件を満たさない間は、照会中に進まず映り方の案内が出る

> 案内は **同じ状態が1秒続いたとき** に出て、状態が解消すると消える。

| 対象 | 顔の映り方 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 利用者 | 遠い | 🟢正常系：画面から離れた位置に立つ | 認証待ちのまま、「画面に少し近づいてください」が出る |
| 利用者 | 近い | 🟢正常系：画面に近づきすぎる | 認証待ちのまま、「画面から少し離れてください」が出る |
| 利用者 | 上にずれる | 🟢正常系：顔の位置を画面の上端寄りにする | 認証待ちのまま、「もう少し下に移動してください」が出る |
| 利用者 | 下にずれる | 🟢正常系：顔の位置を画面の下端寄りにする | 認証待ちのまま、「もう少し上に移動してください」が出る |
| 利用者 | 右にずれる | 🟢正常系：顔の位置を画面の右端寄りにする | 認証待ちのまま、「もう少し左に移動してください」が出る |
| 利用者 | 左にずれる | 🟢正常系：顔の位置を画面の左端寄りにする | 認証待ちのまま、「もう少し右に移動してください」が出る |
| 利用者 | 正面を向いていない | 🟢正常系：顔を上下左右のいずれかに傾ける | 認証待ちのまま、「正面を向いてください」が出る |
| 利用者 | 暗い | 🟡例外系：室内の照明を落とした状態で顔を映す | 認証待ちのまま、「環境が暗すぎる可能性があります 解決しない場合は管理者に問い合わせてください」が出る |
| 利用者 | 明るい | 🟡例外系：顔に強い光が当たる状態で顔を映す | 認証待ちのまま、「環境が明るすぎる可能性があります 解決しない場合は管理者に問い合わせてください」が出る |
| 利用者 | 誰も映っていない | 🟢正常系：カメラの前に誰も立たない | 認証待ちの見出しのままで、映り方の案内は出ない |
| 利用者 | 1秒未満で解消 | 🟢正常系：位置がずれた直後に正しい位置へ戻る | 映り方の案内は出ない |
| 利用者 | 1秒続く | 🟢正常系：ずれた位置のまま1秒以上とどまる | 映り方の案内が出る |
| 利用者 | 案内が出た後に解消 | 🟢正常系：案内が出ている状態から正しい位置に移動する | 映り方の案内が消え、一致すれば照会中に進む |

### ルール⑤: 端末内の顔情報と顔SDKの登録がずれているときは、照会中を経て失敗表示になり、ずれた分がまとめて削除される

| 対象 | 端末内の顔情報 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 従業員 | 顔SDK側にだけ特徴量が残っている | 🟡例外系：その状態で登録済みの本人がカメラに顔を映す | 見出しが「照会中です...」に変わった後、失敗表示になる |

| 対象 | 状況 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |

### ルール⑧: なりすまし防止の設定によって、顔を映してから照会中に進むまでの流れが変わる

| 対象 | なりすまし防止 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |

| 従業員 | 無効 | 🟢正常系：登録済みの本人がカメラに顔を映す | 画面の指示を求められることなく、見出しが「照会中です...」に変わる |

### ❓ 疑問点・未確認事項（赤カード）

- [ ] **認証成功類似度の上限値（1）の扱い。** 一致の判定が「設定値を**超えた**とき」のため、1を設定すると誰も認証できなくなる。上限として1を選べてよいか、または判定を「設定値以上」に変えるかを仕様担当に確認したい。
