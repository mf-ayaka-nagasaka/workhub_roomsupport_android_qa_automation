## ルールの洗い出しと正常系・異常系の分類

### 機能名: QRコードで利用者を特定できる

**機能概要:** カメラ認証画面（予約認証モード用）で、カメラに映ったQRコードから利用者本人を特定し、特定結果を持って操作ごとの画面へ進むまでを扱う。読み取ったQRコードがどの認証失敗にあたるかの振り分けもここで扱う。解錠と入退室の更新はこの画面では行わず、特定結果を受け取った先の画面が行う。

**処理の順序:** ①ホーム画面の操作ボタンからカメラ認証画面に入ると、認証方法にQRコードが含まれる端末ではQRコードの読み取りが始まり、**認証待ち**になる → ②QRコードが読み取られると読み取りが止まり、見出しが**照会中**に変わる → ③読み取ったQRコードから解錠のアクセス権と人物が解決される → ④人物情報を取得し、認証手段をQRコードとした特定結果を持って、操作ごとの画面へ進む。③で解決できないときは、QRコードの中身に応じた認証失敗になる。

**合否の判定:** 画面に出ている要素と、そこに書かれている文言で判定する。

**画面の要素の呼称:**

- **見出し** … 画面上部の案内（「QRコードまたは顔を画面に映してください」「照会中です...」など）
- **失敗の表示** … 認証に失敗したときに出る、エラーメッセージを伴う表示
- **受付の案内** … 受付が済んでいない人のQRコードを読んだときに出る専用の表示（「受付が未完了です」）

### ルール①: 認証方法にQRコードが含まれる端末では、有効なQRコードをかざすと人物が特定され、操作ごとの画面へ進む

> 受け入れ条件⑤（顔認証を採用しないQRのみ運用でも本チケットのみで本人特定が成立する）は、「QRのみ」の行で担保する。

| 対象 | 認証方法 | 操作 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- | :--- |
| 従業員 | QRと顔 | 入室 | 🟢正常系：ホーム画面の「入室」からカメラ認証画面に進み、有効なQRコードをかざす | 見出しが「照会中です...」に変わり、ホーム画面で入室の処理が進む |
| 従業員 | QRと顔 | 退室 | 🟢正常系：「退室」から進み、有効なQRコードをかざす | 見出しが「照会中です...」に変わり、ホーム画面で退室の処理が進む |
| 従業員 | QRと顔 | 今すぐ予約 | 🟢正常系：「今すぐ入室」から進み、有効なQRコードをかざす | 見出しが「照会中です...」に変わり、予約作成の画面が開く |
| 従業員 | QRと顔 | 延長 | 🟢正常系：「延長」から進み、有効なQRコードをかざす | 見出しが「照会中です...」に変わり、延長時間を設定する画面が開く |
| 従業員 | QRと顔 | 予約削除 | 🟢正常系：予約削除の導線から進み、有効なQRコードをかざす | 見出しが「照会中です...」に変わり、ホーム画面で削除の処理が進む |
| 従業員 | QRと顔 | 再解錠 | 🟢正常系：再解錠の導線から進み、有効なQRコードをかざす | 見出しが「照会中です...」に変わり、ホーム画面で解錠の処理が進む |

### ルール②: 読み取ったQRコードの中身によって、どの認証失敗になるかが決まる

> 失敗の表示・受付の案内そのものの見え方、出ている時間、認証待ちへの戻り方は⑭の範囲。ここでは**どのQRコードがどの失敗になるか**だけを見る（台帳 #51）。
>
> アクセス権を取得できなかったQRコードは、続けて受付用のQRコードかどうかが照会される。この照会の打ち切りまでの **5秒** は参照元（iOS）の実装値。

| 対象 | QRコードの種類 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 利用者 | この部屋のアクセス権に人物が紐づかない | 🔴異常系：解錠の権限が無い人のQRコードをかざす | 見出しが「照会中です...」に変わった後、「解錠権限がありません」のメッセージが出る失敗の表示になる |
| ゲスト | 受付が済んでいない人の受付用QRコード | 🔴異常系：受付を済ませていないゲストが自分のQRコードをかざす（照会は打ち切りまでに終わる） | 見出しが「照会中です...」に変わった後、受付の案内（「受付が未完了です」）になる |
| 利用者 | この部屋では使えない／期限が切れていて、受付用でもない | 🔴異常系：他の部屋のQRコード、または期限の切れたQRコードをかざす | 見出しが「照会中です...」に変わった後、「QRコードが不正です」のメッセージが出る失敗の表示になる |
| 利用者 | アクセス権を取得できないQRコード | 🟡例外系：受付用かどうかの照会が通信エラーになる | 見出しが「照会中です...」に変わった後、「インターネットに接続されていません。(CODE: ◯◯)」のメッセージが出る失敗の表示になる |
| 利用者 | 受付が済んでいない人の受付用QRコード | 🟡例外系：受付用かどうかの照会が打ち切りの時間を超える | 受付の案内にはならず、「インターネットに接続されていません。(CODE: ◯◯)」のメッセージが出る失敗の表示になる |

### ルール③: 照会中はQRコードを読み取らず、認証待ちに戻ると読み取りを再開する

| 対象 | 状況 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 従業員 | 同じQRコードを続けてかざす | 🟡例外系：照会中の表示になった直後に、同じQRコードをもう一度かざす | 2回目の照会は始まらず、1回だけ操作ごとの画面へ進む |
| 従業員2名 | 照会中に別の人が割り込む | 🟡例外系：1人目のQRコードで照会中になった直後に、2人目が自分のQRコードをかざす | 2人目の照会は始まらず、1人目の特定結果だけで操作ごとの画面へ1回だけ進む |
| 従業員 | 顔で照会中のときにQRコードをかざす | 🟡例外系：顔が一致して照会中になった直後に、QRコードをかざす | QRコードは読み取られず、顔での特定結果だけで操作ごとの画面へ進む |
| 利用者 | 失敗の後にやり直す | 🟢正常系：失敗の表示が消えて認証待ちに戻った後、有効なQRコードをかざす | 見出しが「照会中です...」に変わり、人物が特定されて操作ごとの画面へ進む |

### ルール④: ネットワークに接続できないときのQRコードでの特定（**期待される振る舞いは保留**）

> QRコードのオフラインモードは**サーバー側から配信される設定**で、端末の設定画面には項目が無い（既定は有効）。参照元（iOS）では、有効のときはネットワークの確認を行わず端末内のキャッシュで照合し、無効のときは「インターネットに接続されていません」の失敗の表示になる。**この振る舞いのままでよいかが未確定のため、期待される振る舞いは保留とする**（台帳 #53・赤カード①）。

| 対象 | QRコードのオフラインモード | ネットワーク | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- | :--- |
| 利用者 | 有効（既定） | 接続できない | 🟡例外系：ネットワークに接続できない状態で、有効なQRコードをかざす | **保留**（リファインメントで確定） |
| 利用者 | 無効 | 接続できない | 🟡例外系：ネットワークに接続できない状態で、有効なQRコードをかざす | **保留**（リファインメントで確定） |

### ❓ 疑問点・未確認事項（赤カード）

- [ ] **ネットワークに接続できないとき、QRコードでの特定をどう振る舞わせるか（ルール④）。** チケット本文のシナリオ「オフライン時のQR認証」の Then が「リファインメントで確定」のままで、オフラインでも特定を成立させるのか、失敗として扱うのかが決まっていない。参照元（iOS）は既定（オフラインモード有効）では端末内のキャッシュで照合し、特定を続ける。**あわせて、この設定を管理画面から切り替えられるか（QAが無効の状態を作れるか）も確認したい。**
- [ ] **同一のQRコードを続けて読んだときの、時間による抑止が常時認証モード専用でよいか。** 受け入れ条件③に「同一QRの連続読み取りで二重処理が起きない」とあるが、参照元では時間による抑止は常時認証モード専用の設定が有効なときだけ効き、予約認証モードではルール③（照会中は読み取らない／認証待ちで再開する）が二重処理を防いでいる。この認識で合っているか（台帳 #50）。
