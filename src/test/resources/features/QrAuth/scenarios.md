# language: ja
機能: QRコードで利用者を特定できる
  会議室のドア前に常設されたタブレットのカメラ認証画面で、カメラに映ったQRコードから利用者本人を特定し、特定結果を持って操作ごとの画面へ進む。読み取ったQRコードがどの認証失敗にあたるかの振り分けもここで扱う。解錠と入退室の更新はこの画面では行わず、特定結果を受け取った先の画面が行う

  背景:
    前提 会議室タブレットは予約認証モードで設定されており、端末の認証方法にQRコードが含まれている

  # ※ カメラ認証画面が表示されること・見出しの出し分け・映り方の案内・戻るボタンは⑪の責務（台帳 #38・#43）
  # ※ 失敗の表示・受付の案内そのものの見え方、出ている時間、認証待ちへの復帰は⑭の責務（台帳 #40・#51）
  # ※ 受付の自動チェックイン／ゲスト通過時の通知、同一のQRコードを続けて読んだときの時間による抑止は常時認証モード専用のため対象外（台帳 #49・#50）
  # ※ 予約作成の画面・延長時間を設定する画面で行う操作と、その可否判定は㉒㉓の責務
  # ※ 読み取りの演出が終わると見出しが照会中に変わるが、特定が演出より早く終わると照会中にならないまま画面が切り替わるため、成功の判定には照会中を使わない

  # ※ カギの有効時間は管理画面の設定（予約開始の◯分前〜予約終了の◯分後）。分数そのものは書かず、有効時間の内側／外側で判定する
  # ※ 参照元(iOS)は有効時間の外側のカギをどちらも「QRコードが不正です」にするが、Android版では「まだ利用できない」「利用できる時間が終わった」を出し分ける方針（文言そのものは⑭）
  # ※ 開始前のケースは、事前入室可能時間がカギの有効時間の前倒し幅より長い設定のときだけ作れる（導線は出ているがカギはまだ無効の状態）
  # ※ 予約に紐づかないカギ（常設の従業員向け・入館用など）の有効期限切れは予約認証モードの運用対象外（rules.md「対象外とする処理」）
  # ※ ホーム画面に操作の導線が出る条件（事前入室可能時間・予約終了後の表示）は⑦⑩⑳の責務。本ルールは導線に到達できた状態からを見る
