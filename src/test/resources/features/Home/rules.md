## ルールの洗い出しと正常系・異常系の分類

### 機能名: ホーム画面の予約状況表示
**機能概要:** 会議室のドア前に常設されたタブレットのホーム画面で、部屋がいま「空室／入室待ち／利用中」のどれなのかを、背景色・中央サークル・主ボタンで一目で判別できるようにする。残り時間は1秒ごとに更新され、予約の作成・削除は他の経路で行われても表示へ反映される。

**状態の判定:** ①利用可能な時間帯でなければ利用不可（「利用不可・利用時間外を表示できる」の責務） → ②現在時刻（事前入室可能時間を含む）に対象の予約が無ければ空室 → ③対象の予約があり入室済みなら利用中 → ④対象の予約があり未入室なら入室待ち。

**責務の切り分け:** 以下は本機能の対象外とし、記載のチケットで検証する（`_master/feature-map.html` の決定台帳を参照）。

| 対象外とする処理 | 移管先のチケット | 台帳 |
| :--- | :--- | :--- |
| 利用不可・利用時間外の表示（主ボタンが表示されないことを含む） | 利用不可・利用時間外を表示できる | #5 #15 |
| 予約の参加者情報の表示 | 予約の参加者情報を表示できる | — |
| 画面下部の予約タイムライン | 当日の予約タイムラインを表示できる | — |
| 入室・退室・延長・再解錠・予約作成の操作と結果、および予約キャンセル・延長・再入室のボタンの表示条件 | 作成済みの予約に入室して解錠できる／入室中の予約から退室できる／今すぐ予約して入室できる／入室中の予約を延長できる／予約をキャンセル・削除できる／入室中の部屋を再解錠できる | #17 |
| 会員向けガイド（空室時の導線とQRコード） | サードプレイス(有料)予約を作成できる | #18 |
| 自動キャンセル・自動延長・予約終了リマインドの実行 | チェックインの無い予約を自動キャンセルできる／入室中の予約を自動延長できる／予約終了リマインドを通知できる | #16 |
| ネットワーク状態の表示、オフライン時の振る舞い | オフライン時のフォールバックを設計・検討できる | — |
| 管理者メニューの起動（ロゴ長押し）、言語切替 | 管理メニューを開いて端末を管理できる／全画面共通 | #14 |
| 空室時オートロック | 作成済みの予約に入室して解錠できる／入室中の部屋を再解錠できる | #19 |

### ルール①: 予約の有無と入室の状況に応じて、ホームは空室・入室待ち・利用中のいずれかで表示される

> 状態が変わると、背景色・中央サークルの見出し・主ボタンのラベルが同時に切り替わる。入室待ちになるのは予約開始時刻そのものではなく、**事前入室可能時間だけ前倒しされた時刻**である。

| 対象 | 予約の状況 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 部屋 | 当日の予約なし | 🟢 正常系：予約が1件も無い状態でホームを表示する | 白基調の「空室」表示。主ボタンは「今すぐ入室」 |
| 部屋 | 事前入室可能時間より前 | 🟢 正常系：30分後に始まる予約があり、事前入室可能時間は10分 | 「空室」表示のまま（20分後に入室待ちへ変わる） |
| 部屋 | 事前入室可能時間に入った未入室の予約 | 🟢 正常系：事前入室可能時間が10分の予約で、開始10分前ちょうどになる | オレンジ基調の「入室待ち」表示。主ボタンは「入室する」 |
| 部屋 | 開始時刻を過ぎた未入室の予約 | 🟢 正常系：予約開始時刻を過ぎても誰も入室していない | 「入室待ち」表示が継続する |
| 部屋 | 入室済みの予約 | 🟢 正常系：予約に入室した状態 | 赤ピンク基調の「利用中」表示。主ボタンは「退室する」 |
| 部屋 | 事前入室可能時間が0 | 🟢 正常系：事前入室可能時間を0に設定し、予約開始時刻ちょうどになる | 開始時刻に「入室待ち」へ切り替わる |

---

### ルール②: 中央サークルには、状態ごとに決められた残り時間が1秒ごとに更新して表示される

> 空室＝入室待ちに変わる時刻まで／入室待ち＝自動キャンセルまで（自動キャンセルが働かない状況では予約終了まで）／利用中＝予約終了まで。1時間以上なら「時:分:秒」、1時間未満なら「分:秒」で表示される。
> **空室のときの表示・非表示の境界は1時間ちょうど**で、残り時間が1時間未満のときだけ表示される。基準は「予約開始時刻 − 事前入室可能時間」であり、空室から入室待ちへ変わる時刻と一致する。

| 対象 | 状態 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 中央サークル | 空室 | 🟢 正常系：入室待ちに変わる時刻まで59分59秒（境界の直前） | 「次の予定まで」と残り時間が表示され、1秒ごとに減る |
| 中央サークル | 空室 | 🟢 正常系：入室待ちに変わる時刻まで1時間ちょうど（境界） | 残り時間は表示されず、「空室」の見出しのみ |
| 中央サークル | 空室 | 🟢 正常系：入室待ちに変わる時刻まで1時間1分（境界の直後） | 残り時間は表示されず、「空室」の見出しのみ |
| 中央サークル | 空室 | 🟢 正常系：当日の予約が1件も無い | 残り時間は表示されず、「空室」の見出しのみ |
| 中央サークル | 入室待ち | 🟢 正常系：自動キャンセルが有効（猶予秒数が1以上）で、チェックイン済みのゲストがいない | 「自動キャンセルまで」と残り時間が表示される |
| 中央サークル | 入室待ち | 🟢 正常系：自動キャンセルが無効 | 「キャンセルまでの残り時間」として、予約終了までの残り時間が表示される |
| 中央サークル | 入室待ち | 🟢 正常系：予約にチェックイン済みのゲストがいる | 自動キャンセルまでではなく、予約終了までの残り時間が表示される |
| 中央サークル | 入室待ち | 🟡 例外系：自動キャンセルの実行に失敗した後 | 自動キャンセルまでではなく、予約終了までの残り時間が表示される |
| 中央サークル | 利用中 | 🟢 正常系：予約終了まで1時間ちょうど（表示形式の境界） | 「01:00:00」の形式（時:分:秒）で表示される |
| 中央サークル | 利用中 | 🟢 正常系：予約終了まで59分59秒（表示形式の境界の直前） | 「59:59」の形式（分:秒）で表示される |

### ルール③: 予約の作成・削除は、他の経路で行われてもホームの表示へ反映される

> 予約データの取得対象は「終了時刻が当日0時以降」かつ「開始時刻が（当日＋設定期間）の終わりまで」の予約で、設定期間の既定は3日。日付が変わると最大1分以内に監視が張り直され、対象期間が繰り上がる。

| 対象 | 予約への操作 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| ホーム画面 | 予約の作成 | 🟢 正常系：空室を表示中に、現在時刻が入室可能時間（予約開始の事前入室可能時間前〜予約終了まで）に重なる予約がWeb等から作成される | 操作なしで「入室待ち」表示へ切り替わる |
| ホーム画面 | 予約の作成 | 🟢 正常系：空室を表示中に、2時間後に始まる予約がWeb等から作成される | 「空室」表示のまま変わらない |
| ホーム画面 | 予約の削除 | 🟢 正常系：入室待ちを表示中に、その予約がWeb等から削除される | 操作なしで「空室」表示へ戻る |
| ホーム画面 | 他端末での入室 | 🟢 正常系：同じ空間に設置された別のタブレットで入室が行われる | 「利用中」表示へ切り替わる |
| ホーム画面 | 日付のまたぎ | 🟢 正常系：23:50〜翌0:30 の予約に入室した状態で日付が変わる | 「利用中」表示と残り時間が途切れずに続く |
| ホーム画面 | 日付のまたぎ | 🟢 正常系：翌0:00 開始の予約がある状態で日付が変わる | 日付の変更から1分以内に「入室待ち」へ切り替わる |
| ホーム画面 | 取得対象期間の外 | 🟢 正常系：4日後に始まる予約がWeb等から作成される（設定期間が既定の3日） | 表示は変わらない |

### ルール④: 予約が切り替わったときに、状態が正しく引き継がれる

| 対象 | 直前の状態 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| ホーム画面 | 利用中 | 🟢 正常系：利用中の予約が終わり、続けて次の予約の時間に入る | 「入室待ち」表示へ切り替わる（利用中のままにならない） |
| ホーム画面 | 利用中 | 🟢 正常系：利用中の予約が終わり、次の予約が無い | 「空室」表示へ切り替わる |

### ルール⑤: 主ボタンは、部屋の状態と端末の設定に応じて表示・非表示が決まる

> ラベルは状態ごとに「今すぐ入室」「入室する」「退室する」と変わる。押した後の動きは各操作のチケットの責務で、本ルールは**ボタンが出るか出ないか**を対象とする。
> 参照元（iOS）にある「ホーム表示後7秒間はボタンを隠す」挙動は、Android版では採らない（台帳 #8・#12 により、データが揃ってからホーム画面へ遷移するため）。

| 対象 | 状態 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 主ボタン | 空室 | 🟢 正常系：起動準備が終わりホームに到達した直後 | 待ち時間なく「今すぐ入室」が表示される |
| 主ボタン | 空室 | 🟢 正常系：「予約作成（今すぐ入室）」の設定が有効 | 「今すぐ入室」が表示される |
| 主ボタン | 空室 | 🔴 異常系：「予約作成（今すぐ入室）」の設定が無効 | 主ボタンは表示されない |
| 主ボタン | 入室待ち | 🟢 正常系：「入室」の設定が有効 | 「入室する」が表示される |
| 主ボタン | 入室待ち | 🔴 異常系：「入室」の設定が無効 | 主ボタンは表示されない |
| 主ボタン | 利用中 | 🟢 正常系：「退室」の設定が有効 | 「退室する」が表示される |
| 主ボタン | 利用中 | 🔴 異常系：「退室」の設定が無効 | 主ボタンは表示されない |

### ルール⑥: 空間名はヘッダー中央に表示され、表示領域に収まらない幅のときは自動でスクロールする

> スクロールするかどうかは文字数ではなく**文字列の幅と表示領域の幅の比較**で決まる。表示領域の幅は `画面幅 × 0.9 −（ロゴ140 + 余白40）−（言語切替90 + 余白40）`、文字サイズは50。
> 対象端末（KC-T306／10.1型・1920×1200・倍率1.5として算出）では、縦向きの表示領域が410dpとなり**全角8文字までは静止、9文字からスクロール**する（横向きは全角16文字まで静止、17文字からスクロール）。

| 対象 | 空間名 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| ヘッダー | 表示領域に収まる長さ | 🟢 正常系：全角8文字の空間名（縦向き・境界） | 全体が静止して表示される |
| ヘッダー | 表示領域に収まらない長さ | 🟢 正常系：全角9文字の空間名（縦向き・境界の直後） | 1.5秒後に一方向のスクロールが始まり、末尾まで読める状態が繰り返される |
| ヘッダー | 表示領域に収まらない長さ | 🟢 正常系：全角40文字の空間名 | 同様にスクロールし、途中で欠けずに末尾まで読める |

### ルール⑦: 端末が判定した部屋の状態は共有され、同じ空間の他の端末にも追随する

> 受け入れ条件の「サーバへの反映」「反映の確定待ち」を、観測できる結果に言い換えたもの。自動ステータス更新を無効にした端末は自ら更新せず、他の端末による更新を待つ。

| 対象 | 自動ステータス更新の設定 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 同じ空間の2台目の端末 | 有効 | 🟢 正常系：1台目で状態が入室待ちへ変わる | 2台目のホームも入室待ちへ追随する |
| 端末 | 有効 | 🟢 正常系：状態が切り替わる | 表示が別の状態に揺れ戻ることなく、新しい状態で確定する |
| 端末 | 無効 | 🟢 正常系：自動ステータス更新を無効にした端末で予約の時間に入る | 自らは状態を更新せず、他の端末が更新するまで表示が変わらない |

---

### ルール⑧: 設置空間が未設定の端末では、ホーム画面は表示されず設定画面へ移る

> 現在の参照元（iOS）の挙動に沿ったルール。「値なし」と「空文字」で扱いが分かれており、空文字は未設定として検知されない（赤カード①）。

| 対象 | 設置空間の値 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| ホーム画面 | 未設定（値なし） | 🔴 異常系：設置空間が未設定の端末でホーム画面に到達する | ホーム画面は表示されず、設定画面へ移る |
| ホーム画面 | 未設定（空文字・空白のみ） | 🔴 異常系：設定画面で空の設置空間が保存された端末でホーム画面に到達する | 未設定として扱われず、ホーム画面がそのまま表示される（予約を取得できないため空室のまま変わらない） |
| ホーム画面 | 設定済み | 🟢 正常系：設置空間が設定されている | 通常どおりホーム画面が表示される |

---

### ルール⑨: 「利用中」なのに表示対象の予約が手元に無いときは、最後に入室した予約から表示を復旧する

> 現在の参照元（iOS）の挙動に沿ったルール。復旧できるのは、その端末で入室した予約が**現在時刻も予約時間内**である場合に限られる（赤カード②）。

| 対象 | 端末内の記録 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| ホーム画面 | 最後に入室した予約あり（現在時刻が予約時間内） | 🟡 例外系：利用中の状態を受け取ったが、表示対象の予約が無い | 記録された予約を取り直し、残り時間を含む利用中の表示になる |
| ホーム画面 | 最後に入室した予約あり（予約時間外） | 🟡 例外系：記録された予約の終了時刻を過ぎている | 復旧せず、予約の無い状態のままとなる |
| ホーム画面 | 記録なし | 🟡 例外系：入室の記録が端末に無い | 復旧は行われない |

### ❓ 疑問点・未確認事項（赤カード）

- [ ] **①** 設置空間が未設定のときの扱い（**リファインメントへの提案**）。現状は「値なし＝設定画面へ遷移／空文字＝素通り」で、空文字のまま予約を実行すると原因の分からない汎用エラーになる（台帳 #13）。提案：値なし・空文字・空白のみを同じ未設定として扱い、主ボタンを押した時点で「スペースが未設定です。管理者にお問い合わせください」旨のエラーを表示する（管理者は設定画面で空になっていることを確認して保存し直す）。
- [ ] **②** 参照元（iOS）の「利用中なのに予約が無いときの復旧」を Android版へ移植するか（**リファインメントの議題**／台帳 #20）。台帳 #8・#12 の「揃うまでホーム画面へ遷移しない」方針のもとで発生し得るかは未確認。
