## ルールの洗い出しと正常系・異常系の分類

### 機能名: 予約の参加者情報表示

**機能概要:** 会議室のドア前のタブレットのホーム画面で、いま表示されている予約の主催者と参加メンバーを、予約ごとの公開範囲の設定に従って表示する。表示される場所は、中央サークルと主ボタンの間（横向きのときは中央サークルの右）の**参加者情報エリア**。

**処理の順序:** ①表示するかどうかを決める（端末設定「予約情報の表示」／部屋の状態／予約に参加者がいるか） → ②参加者リスト全員の人物情報を一括で取得し、主催者の人物情報は別に取得する（どちらも取得できないときは10秒間隔で最大5回まで再試行する） → ③主催者のアイコン画像を取得する → ④主催者名と参加メンバー名（最大3名）を組み立てる → ⑤公開範囲に従って表示する。

**合否の判定:** 画面に**どの要素が出ているか・そこに何と書かれているか**で判定する。色・配置の見た目は検証対象としない（⑦⑧で決めた方針に合わせる）。

**責務の切り分け:** 以下は本機能の対象外とし、記載のチケットで検証する（`_master/feature-map.html` の決定台帳を参照）。

| 対象外とする処理 | 移管先のチケット | 台帳 |
| :--- | :--- | :--- |
| 利用不可・利用時間外のときに参加者情報が出ないこと（画面全体が差し替わる） | 利用不可・利用時間外を表示できる | #15 |
| 入室・退室・延長・再解錠などの操作中に参加者情報エリアが出ないこと | 作成済みの予約に入室して解錠できる／入室中の予約から退室できる／入室中の予約を延長できる／予約をキャンセル・削除できる／入室中の部屋を再解錠できる | #29 |
| サードプレイスの顧客が関わる予約のホーム表示と、そのアイコン画像の取得 | サードプレイス(有料)予約を作成できる | #30 |
| 端末設定「予約情報の表示」を変更する操作 | 管理者が予約認証の設定を変更できる | — |
| タイムラインの予約の詳細に出る主催者名・件名 | 当日の予約タイムラインを表示できる | #24 #31 |
| ホーム画面に着くまでの待ち時間と、予約データの揃え方 | 起動時に予約データを準備してホームを表示できる | #8 #12 #27 |
| 部屋の状態そのものの切り替わり（利用中→空室、入室待ち→空室など）の判定と、自動キャンセルの実行 | ホーム画面の予約状況表示（ルール④）／チェックインの無い予約を自動キャンセルできる | #9 #16 |
| 表示言語を切り替える操作そのもの | 全画面共通 | #14 |
| 主催者のアイコン画像の取得に失敗したときのフォールバック表示 | — | #32 画像表示ライブラリ（Coil）の責務のため検証対象外 |
| 「予約を作成した人が参加者リストに含まれない」というデータの形が作られるかどうか | — | サーバ側のデータ仕様のため検証対象外。アプリ側はその形を受け取ったときの表示を単体テストで担保する |
| 取得の多重実行の防止、更新が止まっている間の内部の振る舞い | — | 画面から観測できないため検証対象外 |

### ルール①: 参加者情報エリアが出るのは、予約情報の表示が有効で、部屋が入室待ち・利用中で、予約に参加者がいるときだけ

> 3つの条件のうち1つでも欠けると、公開範囲の設定に関わらずエリアは1つも表示されない。主催者以外の参加者が1人も登録されていない場合に参加メンバーの行が表示されないことは、**ルール④**で担保する。

| 対象 | 端末設定「予約情報の表示」 | 部屋の状態 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- | :--- |
| 参加者情報エリア | 有効 | 入室待ち | 🟢 正常系：公開範囲が全公開（all）で参加者が3人いる予約が入室待ちになっている | 中央サークルと主ボタンの間に主催者と参加メンバーが表示される |
| 参加者情報エリア | 有効 | 利用中 | 🟢 正常系：同じ予約に入室した | 利用中の表示に変わっても、引き続き主催者と参加メンバーが表示される |
| 参加者情報エリア | 有効 | 空室 | 🔴 異常系：当日の予約が1件も無く空室である | 参加者情報エリアは表示されず、中央サークルと主ボタンだけになる |
| 参加者情報エリア | 無効 | 入室待ち | 🔴 異常系：公開範囲が全公開（all）の予約が入室待ちだが、端末設定「予約情報の表示」が無効である | 参加者情報エリアは表示されない |

---

### ルール②: 予約ごとの公開範囲によって、エリアに出る内容が変わる

> 公開範囲は予約ごとにWeb側で設定された値。**非公開（none）＝エリアごと出ない／主催者のみ公開（owner）＝主催者の行だけ／全公開（all）＝主催者の行＋参加メンバー名＋「他N名」**。

| 対象 | 公開範囲 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 参加者情報エリア | 全公開（all） | 🟢 正常系：主催者1人＋従業員の参加メンバー4人（計5人）の予約が入室待ちである | 主催者の行と参加メンバーの名前、さらに「他1名」が表示される |
| 参加者情報エリア | 主催者のみ公開（owner） | 🟢 正常系：同じ参加者構成で公開範囲だけを主催者のみ公開にする | 主催者の行だけが表示され、参加メンバーの名前も「他N名」も表示されない |
| 参加者情報エリア | 非公開（none） | 🟢 正常系：同じ参加者構成で公開範囲だけを非公開にする | 参加者情報エリアが1行も表示されない |

---

### ルール③: 主催者はアイコン・氏名・「主催者」ラベルの並びで1行に表示される

> 主催者は、**予約を作成した人と一致する参加者**。一致する参加者がいない予約では、参加者リストの先頭の人が主催者として扱われる（一致の判定は `personaId` の突き合わせ）。**このデータの形がWeb側の操作で作られるかはサーバ側の仕様のため対象外**とし、アプリ側はその形を受け取ったときの表示を単体テストで担保する。ラベルは日本語表示で「主催者」、英語表示で「Host」。
> 主催者の行に**所属組織名は併記されない**（タイムラインの予約の詳細に出る会社名〈チケット⑧〉とは異なる）。ただしテナント組織の予約では、氏名の位置そのものが組織名になる（**ルール⑧**）。
> 主催者の行に出る名前は **①人物情報に登録された氏名 → ②取れなければ予約データに入っている名前 → ③どちらにも無ければエリアごと出ない** の順で決まる。人物情報を取得できないときは**10秒間隔で最大5回まで再試行**してから②へ移る。取得が失敗するのは、通信が切れている・サーバーがエラーを返す・対象の人物が組織から削除されている・テナント組織を参照できないとき。

| 対象 | 条件 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 主催者の行 | 予約を作成した人が参加者に含まれる | 🟢 正常系：参加者3人のうち1人が予約を作成した人である予約が入室待ちである | 予約を作成した人の氏名が、アイコンと「主催者」ラベルを伴って1行目に表示される |
| 主催者の行 | 表示言語が英語 | 🟢 正常系：同じ予約の表示中に表示言語を英語にする | ラベルが「Host」で表示される |
| 主催者の行 | 予約を作成した人が参加者に含まれない | 🟡 例外系：予約を作成した人が参加者リストに含まれていない予約が入室待ちである | 参加者リストの先頭の人が主催者として1行目に表示される |
| 主催者の行 | 人物情報を取得できない | 🟡 例外系：主催者の人物情報の取得が10秒間隔で5回とも失敗する | 予約データに入っている名前で表示される |
| 主催者の行 | 主催者の氏名がどこにも入っていない | 🟡 例外系：主催者の人物情報にも予約データにも氏名が入っていない | 参加者情報エリアが1行も表示されない（参加メンバーも出ない） |

---

### ルール④: 参加メンバーの名前は、従業員だけが主催者を除いて最大3名まで1行に並ぶ

> 名前が並ぶのは**従業員**だけで、従業員以外（ゲスト）は名前が出ない（人数としてはルール⑤の「他N名」に含まれる）。名前は読点ではなくカンマ区切りで1行に連ねて表示される。**上限は3名ちょうど**で、4人目以降は名前が出ない。
> 名前の候補になるのは**参加者リスト全員**で、リストの何番目にいる従業員でも名前が並ぶ。従業員が4人以上いる場合に名前が並ぶ3人は、参加者リストの先頭に近い順で決まる（並び順はサーバー側が決める）。
> 1人あたりの表示は**日本語で全角6文字・英語で半角13文字**までで、これを超える名前は上限から「…」の分を引いた長さ＋「…」（**日本語は5文字＋「…」／英語は11文字＋「…」**）に切り詰めて表示される。長い名前があっても**並ぶ人数は減らない**。この文字数は、参加者情報エリアの幅と参加メンバーの行の文字サイズから、3人が1行に収まる長さとして決めたもの。

| 対象 | 参加者の構成 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 参加メンバーの行 | 主催者のみ | 🟢 正常系：公開範囲が全公開で、参加者が主催者1人だけの予約が入室待ちである | 主催者の行だけが表示され、参加メンバーの行は表示されない |
| 参加メンバーの行 | 従業員3人（境界ちょうど） | 🟢 正常系：主催者＋従業員の参加メンバー3人（計4人）の予約が入室待ちである | 従業員3人の名前がカンマ区切りで並ぶ |
| 参加メンバーの行 | 従業員4人（境界の直後） | 🟢 正常系：主催者＋従業員の参加メンバー4人（計5人）の予約が入室待ちである | 名前が並ぶのは3人までで、4人目の名前は表示されない |
| 参加メンバーの行 | ゲストが混ざる | 🟢 正常系：主催者（従業員）＋従業員1人＋ゲスト2人（計4人）の予約が入室待ちである | 名前が並ぶのは従業員1人だけで、ゲスト2人の名前は表示されない |
| 参加メンバーの行 | ゲストを先に追加している | 🟢 正常系：主催者のあとにゲスト2人、そのあとに従業員3人の順で追加された（計6人）予約が入室待ちである | 追加した順に関わらず従業員3人の名前が並び、「他2名」が表示される |
| 参加メンバーの行 | 名前が上限ちょうど（日本語） | 🟢 正常系：日本語名が全角6文字の従業員3人＋主催者（計4人）の予約が入室待ちである | 3人とも省略されずに名前が並ぶ |
| 参加メンバーの行 | 名前が上限を超える（日本語） | 🟢 正常系：日本語名が全角7文字の従業員3人＋主催者（計4人）の予約が入室待ちである | 3人とも先頭5文字＋「…」で表示され、並ぶ人数は3人のまま |
| 参加メンバーの行 | 名前が上限ちょうど（英語） | 🟢 正常系：表示言語が英語で、英語名が半角13文字の従業員3人＋主催者（計4人）の予約が入室待ちである | 3人とも省略されずに名前が並ぶ |
| 参加メンバーの行 | 名前が上限を超える（英語） | 🟢 正常系：表示言語が英語で、英語名が半角14文字の従業員3人＋主催者（計4人）の予約が入室待ちである | 3人とも先頭11文字＋「…」で表示され、並ぶ人数は3人のまま |

---

### ルール⑤: 名前が出なかった人数は「他N名」で示される

> N ＝ **参加者の総数 − 名前が並んだ参加メンバーの人数 − 1（主催者）**。参加者の総数は**予約データの参加者リスト全員**の人数。Nが0以下のときはこの行自体が出ない。文言は日本語表示で「他N名」、英語表示で「+N others」。
> 名前が出なかった人には、上限の3名を超えた従業員だけでなく、従業員以外（ゲスト）や、人物情報を取得できなかった人も含まれる。参加メンバーの人物情報は**一括で取得**するため、取得に失敗したときは**参加メンバー全員**が「他N名」に含まれる（主催者の取得は別。ルール③のとおり）。

| 対象 | 参加者の構成 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 「他N名」の行 | 計4人（境界ちょうど） | 🟢 正常系：主催者＋従業員の参加メンバー3人（計4人）の予約が入室待ちである | 名前が3人並び、「他N名」の行は表示されない |
| 「他N名」の行 | 計5人（境界の直後） | 🟢 正常系：主催者＋従業員の参加メンバー4人（計5人）の予約が入室待ちである | 名前が3人並び、「他1名」が表示される |
| 「他N名」の行 | 計4人・ゲスト混在 | 🟢 正常系：主催者（従業員）＋従業員1人＋ゲスト2人（計4人）の予約が入室待ちである | 名前は従業員1人だけが並び、「他2名」が表示される |
| 「他N名」の行 | 英語表示 | 🟢 正常系：表示言語が英語の状態で、主催者＋従業員の参加メンバー4人（計5人）の予約が入室待ちである | 「+1 others」が表示される |
| 「他N名」の行 | 参加メンバーの人物情報を取得できない | 🟡 例外系：参加メンバーの人物情報の一括取得が10秒間隔で5回とも失敗する | 参加メンバーの名前は1人も表示されず、全員が「他N名」の人数に含まれる |

---

### ルール⑥: 氏名は表示言語に合わせて切り替わり、英語名が無い人は日本語名で表示される

> 日本語表示なら日本語名、英語表示なら英語名。ただし**英語名が未登録（空、または「-」）の人**は、英語表示でも日本語名で表示される。主催者・参加メンバーのどちらにも同じ扱いが適用される。

| 対象 | 表示言語 | 英語名の登録 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- | :--- |
| 氏名 | 日本語 | 登録あり | 🟢 正常系：日本語名と英語名の両方が登録された主催者の予約が入室待ちである | 日本語名で表示される |
| 氏名 | 英語 | 登録あり | 🟢 正常系：同じ予約で表示言語を英語にする | 英語名で表示される |
| 氏名 | 英語 | 空 | 🟡 例外系：英語名が未登録（空）の参加メンバーがいる | その人だけ日本語名で表示され、他の人は英語名のまま |
| 氏名 | 英語 | 「-」 | 🟡 例外系：英語名に「-」が登録された参加メンバーがいる | その人だけ日本語名で表示される（「-」は表示されない） |

---

### ルール⑦: 主催者のアイコンは、画像が無いときは既定の人型アイコンになる

> アイコンが付くのは**主催者だけ**で、参加メンバーの名前にはアイコンが付かない。アイコンの枠は常に1つ表示され、画像の有無で中身だけが変わる。

| 対象 | 主催者のアイコン画像 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 主催者のアイコン | 登録あり | 🟢 正常系：アイコン画像が登録された従業員が主催者の予約が入室待ちである | 登録された画像が円形で表示される |
| 主催者のアイコン | 登録なし | 🟢 正常系：アイコン画像を登録していない従業員が主催者の予約が入室待ちである | 既定の人型アイコンが表示される |
| 参加メンバー | — | 🟢 正常系：アイコン画像が登録された従業員が参加メンバーに含まれる | 参加メンバーの名前にアイコンは付かない |

---

### ルール⑧: テナント組織の予約では、主催者の行に氏名ではなく組織名が表示され、参加メンバーの名前は1人も並ばない

> 予約を作成した人の組織が、このタブレットがログインしている組織と違う場合（マルチテナント関係にあるテナント組織からの予約）の振る舞い。**2026-11-11 に実機で確認済み。**
> - 主催者の行には**個人名ではなくテナント組織の組織名**が表示される（アイコンと「主催者」ラベルの並びはルール③と同じ）。
> - 参加メンバーの名前は**1人目から1人も並ばず**、主催者を除く全員が「他N名」に入る（名前が並ぶのは従業員だけ、というルール④の絞り込みの結果）。
> - この切り替えは**予約を作成した人の組織**で決まり、主催者・参加メンバーの全員に同じ組織が使われる。
>
> ログイン中の組織の予約の場合は**ルール③・ルール④**のとおり（主催者は個人名、従業員の名前は最大3名まで並ぶ）。人物情報を取得できないときのフォールバックは所属によらず同じで、**ルール③・ルール⑤**に書いてある。

| 対象 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- |
| 主催者の行 | 🟢 正常系：テナント組織のユーザーが主催者の予約が入室待ちである | 個人名は表示されず、**テナント組織の組織名**が表示される |
| 参加メンバーの行 | 🟢 正常系：公開範囲が全公開で、テナント組織のユーザーだけで構成された参加者3人の予約が入室待ちである | 参加メンバーの名前は1人も表示されず、「他2名」が表示される |

---

### ルール⑨: 表示対象の予約が切り替わると、参加者情報も次の予約のものに切り替わる

> 表示対象の予約が替わるきっかけは、**利用中の予約が終了時刻を過ぎる／入室待ちの予約が自動キャンセルされる／自動キャンセルが無効のまま終了時刻を過ぎる／他の経路で予約が作成・削除される**など。次の予約が続いていれば**その予約の参加者情報に入れ替わり**、次の予約が無ければ空室になって**エリアごと表示されなくなる**。
> **部屋の状態そのものの切り替わりの判定**（利用中→入室待ち、入室待ち→空室 など）は⑦「ホーム画面の予約状況表示」ルール④の責務。本ルールは、その切り替わりに**参加者情報エリアの中身が追従すること**だけを対象とする。
> 切り替わりは **①出ている→中身が変わる ②出ている→出なくなる ③出ていない→出るようになる** の3通り。③は、前の予約で非公開などによりエリアが出ていない状態から、次の予約で出るようになる場合。
> 認証画面などホーム画面を離れて戻ってきたときは、離れる前に表示していた参加者情報がそのまま引き継がれる。

| 対象 | きっかけ | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 参加者情報エリア | 利用中の予約が終了時刻を過ぎ、次の予約が続く | 🟢 正常系：主催者Aの予約を利用中に終了時刻を過ぎ、続けて主催者Bの予約の時間に入る | 主催者の行がBに入れ替わり、参加メンバーの名前もBの予約のものになる |
| 参加者情報エリア | 利用中の予約が終了時刻を過ぎ、次の予約が無い | 🟢 正常系：主催者Aの予約を利用中に終了時刻を過ぎ、当日の次の予約が無い | 参加者情報エリアが表示されなくなる |
| 参加者情報エリア | 入室待ちの予約が自動キャンセルされ、次の予約が続く | 🟢 正常系：入室待ちの主催者Aの予約が自動キャンセルされ、続けて主催者Bの予約が入室待ちになる | 主催者の行がBに入れ替わり、参加メンバーの名前もBの予約のものになる |
| 参加者情報エリア | 入室待ちの予約が自動キャンセルされ、次の予約が無い | 🟢 正常系：入室待ちの予約が自動キャンセルされ、当日の次の予約が無い | 参加者情報エリアが表示されなくなる |
| 参加者情報エリア | 自動キャンセルが無効のまま終了時刻を過ぎる | 🟢 正常系：自動キャンセルが無効の予約が入室されないまま終了時刻を過ぎ、当日の次の予約が無い | 参加者情報エリアが表示されなくなる |
| 参加者情報エリア | 公開範囲が違う予約への入れ替わり | 🟢 正常系：公開範囲が全公開の予約が終わり、続けて非公開の予約が入室待ちになる | 参加者情報エリアが表示されなくなる |
| 参加者情報エリア | 参加者がいない予約への入れ替わり | 🟢 正常系：公開範囲が全公開の予約が終わり、続けて参加者が1人も登録されていない予約が入室待ちになる | 参加者情報エリアが表示されなくなる |
| 参加者情報エリア | 出ていない状態から出る状態への入れ替わり | 🟢 正常系：公開範囲が非公開の予約（エリアが出ていない状態）が終わり、続けて全公開の予約が入室待ちになる | 参加者情報エリアが表示されるようになり、次の予約の主催者と参加メンバーが出る |
| 参加者情報エリア | 画面を離れて戻る | 🟡 例外系：参加者情報が表示された状態で認証画面へ進み、操作せずにホーム画面へ戻る | 戻った直後から、離れる前と同じ主催者・参加メンバーが表示されている |

### ルール⑩: 同じ予約のまま参加者が差し替わっても、表示は新しい参加者に更新される

> 参加者の人数が変わると、増減したのが従業員でもゲストでも取得し直される。
> **2026-11-11 に実機で確認**：主催者の従業員をWeb側で削除しても、その人は予約の参加者リストに残り続け（管理画面上も主催者のまま）、タブレットの表示も変わらない。予約を作成した人を参加者リストから外す手段は、Web側の操作では見つかっていない。参加者の**人数が変わらない差し替え**（1人外して1人追加する）でも更新される。参照元（iOS）は人数の比較だけで再取得を判断するため更新されないが、Android版では更新されることを正しい振る舞いとする（台帳 #28、**赤カード②**）。

| 対象 | 参加者の変化 | 実例（データ・状況の組み合わせ） | 期待される振る舞い |
| :--- | :--- | :--- | :--- |
| 参加メンバーの行 | 人数が増える | 🟢 正常系：公開範囲が全公開・主催者＋従業員1人の予約が入室待ちの状態で、Web側から従業員をもう1人追加する | 追加された従業員の名前が並びに加わる |
| 参加メンバーの行 | 人数が減る | 🟢 正常系：同じ状態からWeb側で参加メンバーを1人削除する | 削除された従業員の名前が並びから消える |
| 参加メンバーの行 | 人数が変わらない差し替え | 🟢 正常系：主催者＋従業員2人の予約が入室待ちの状態で、Web側で従業員1人を外して別の従業員1人を追加する | 外された従業員の名前が消え、追加された従業員の名前が表示される |
| 主催者の行 | 主催者の入れ替わり | 🟡 例外系：同じ予約で予約を作成した人が参加者リストから外れる | 参加者リストの先頭の人が主催者として表示され、氏名とアイコンがその人のものに変わる |
| 「他N名」の行 | ゲストが増える | 🟢 正常系：公開範囲が全公開・主催者＋従業員1人の予約が入室待ちの状態で、Web側からゲストを1人追加する | 名前の並びは変わらず、「他1名」が表示される |
| 「他N名」の行 | ゲストが減る | 🟢 正常系：公開範囲が全公開・主催者＋従業員1人＋ゲスト1人の予約が入室待ちの状態で、Web側でゲストを削除する | 名前の並びは変わらず、「他1名」が表示されなくなる |
